# im-prd-skill

[English](README.md) | [简体中文](README.zh-CN.md) | [繁體中文](README.zh-TW.md) | [日本語](README.ja.md) | [한국어](README.ko.md) | [Español](README.es.md) | [Português](README.pt.md) | [Français](README.fr.md)

메시징(IM) 및 소셜 제품의 PRD를 작성하기 위한 Claude Agent Skill입니다. 주요 메시징 앱이 각 기능을 어떻게 처리하는지 정리한 26개 모듈의 라이브러리를 포함하고 있어, 생성된 명세가 기본적으로 IM 관례를 따릅니다. 주요 앱 사이에서 실제로 방식이 갈리는 지점만 객관식 질문으로 의사결정자에게 묻습니다. Markdown 납품 초안만 만들 수도 있고, 주석 카드를 Figma 캔버스에 함께 작성할 수도 있습니다.

이 스킬은 ZYMIX 팀을 위해 만들어졌습니다. 이 공개 버전에서는 팀의 Figma 파일 키, 디자인 시스템 값, 내부 결정 사항, 원본 증거 자료를 제거했으며, 워크플로, 규칙 라이브러리, 템플릿, 스크립트, 평가 케이스는 그대로 들어 있습니다.

## 해결하는 문제

AI에게 IM 기능 명세를 곧바로 쓰게 하면 보통 세 가지 문제가 생깁니다. 확실하지 않은 규칙이 확정된 것처럼 쓰입니다. 정상 흐름만 다루고, 차단, 계정 삭제, 오프라인, 멀티 디바이스, 그룹과 1:1의 차이 같은 상태가 빠집니다. 업계 관례와 팀이 실제로 결정해야 하는 몇 가지 사항이 뒤섞여, 의사결정자가 전부 읽어야 그것을 찾을 수 있습니다.

이 스킬이 처리하는 방법은 다음과 같습니다.

- **3단계 규칙 라이브러리**: 기준선(주요 앱이 일치하며 기본적으로 따름), 관례(대부분의 앱이 그렇게 하며 기본값은 권장안), 분기점(앱마다 다르며 Must-ask(필수 질문) 또는 Default-OK(기본값 가능)로 표시).
- **필수 질문만 묻기**: 한 라운드에 객관식 질문은 최대 4개이며, 권장 선택지를 맨 앞에 둡니다. 나머지는 모두 권장안대로 작성하고, 검토할 수 있도록 "Defaulted to recommendation"(권장안으로 기본 처리한 항목) 아래에 한 줄씩 나열합니다.
- **상태 커버리지 매트릭스**: 성공, 실패, 시간 초과, 오프라인, 권한, 멀티 디바이스 동기화, 그리고 "상대방이 나를 차단함 / 계정을 삭제함 / 그룹을 나감" 같은 상태를 하나씩 점검합니다.
- **불확실성을 그대로 드러내기**: 결정이 필요한 항목은 `{TBD: topic, recommended: approach}`로, 빠진 사실은 `{TBC: what is missing}`으로 씁니다. 확정되지 않은 것을 확정된 것처럼 넘기지 않습니다.
- **쓰기 게이트**: Figma를 건드리기 전에 생성할 모든 노드와 배치를 나열하고, 의사결정자가 승인한 뒤에야 캔버스에 씁니다.

## 워크플로

| 단계 | 내용 |
|---|---|
| 0 제품 정리 | 대화 유형(1:1 / 그룹 / 채널 / 커뮤니티), 플랫폼, 종단 간 암호화 여부, 낯선 사람이 연락할 수 있는지, 실현 가능성 전제 조건을 확인 |
| 1 기준 자료 고정 | Figma 파일과 노드를 기록하고, 각 요구사항을 정의됨 / 확인 필요 / 제안으로 표시 |
| 2 IM 규범 점검 | 해당하는 모듈을 읽고, 기준선은 따르고, 관례는 기본값으로 하며, 분기점은 등급에 따라 처리 |
| 3 경쟁 제품 참고 | 라이브러리가 다루지 않는 기능에 한해서만 외부 조사 |
| 4 상태 커버리지 매트릭스 | 일반 차원과 모듈별 필수 질문 상태를 각각 반영됨 / 해당 없음 / 미정의로 표시 |
| 5 초안 먼저 | Markdown 납품 초안을 쓰고 `lint_card_text.py`를 실행. 큰 초안에는 독자 테스트를 추가 |
| 6 레이아웃과 번호 매기기 | 화면 순서, 행, 번호를 한 번에 계획 |
| 7 쓰기 게이트 | `lint_card_text.py --gate`를 통과하고 의사결정자가 승인하기 전에는 아무것도 쓰지 않음 |
| 8 카드 작성과 자체 점검 | 배치마다 자체 점검하고, 마지막에 인수 확인서를 제출 |

납품 초안 순서: Decisions for Box(Box의 결정 사항) → Defaulted to recommendation → Open items(미결 항목) → Role view summary(역할별 요약) → Cards(카드) → Feature list(기능 목록) → Acceptance checkpoints(인수 확인 항목, ≤ 12) → Suggested follow-ups(후속 제안).

## 구조

```
en/box-prd-create/              # 영어 에디션 (zh-CN/도 같은 구조)
├── SKILL.md                    # 워크플로와 라우팅 (진입점)
├── references/
│   ├── im-norms/               # 26개 IM 모듈 + 안티패턴 + 소유 표
│   ├── draft-template.md       # 납품 초안 및 작업 노트 템플릿
│   ├── self-check.md           # 납품 자체 점검
│   ├── canvas-layout.md        # Figma 캔버스 레이아웃
│   ├── figjam.md               # 플로차트와 기능 목록
│   ├── design-system.md        # 디자인 시스템 (템플릿, 직접 채우기)
│   ├── rulings.md              # 결정 사항 (템플릿, 직접 채우기)
│   └── HISTORY.md              # 변경 이력
└── scripts/
    ├── lint_card_text.py       # 카드 텍스트 lint (--gate는 쓰기 게이트용)
    ├── lint_skill.py           # 규칙 라이브러리 구조 자체 점검
    └── brand_terms.txt         # 사용 금지 브랜드 이름
```

모듈: 계정과 기기, 연락처와 개인정보, 채팅 목록, 전송과 수신 확인, 메시지 동작, 미디어와 파일, 그룹과 채널, 알림, 안전과 보안, 검색/통화/저장 공간, 페이지 구조, 상호작용 패턴, 서비스 계정과 봇, 채팅 내 결제, 피드/채널/커뮤니티, 리치 메시지, 번역과 AI, 탐색/로그인/권한, 지갑 계정, 초대와 성장, 연령과 미성년자, 제재와 이의 제기, 광고와 개인화, 포인트와 멤버십, 개인정보 센터, 지원 티켓.

## 설치

Claude Code (영어 에디션 기준이며, 중국어는 `zh-CN/box-prd-create`를 사용):

```bash
git clone https://github.com/ZBoxMan/im-prd-skill.git
```

```bash
cp -R im-prd-skill/en/box-prd-create ~/.claude/skills/
```

## 사용법

기능을 설명하기만 하면 됩니다. 예를 들어:

- "그룹 채팅에 그룹 공지 기능을 추가해 줘. PRD를 써 줘. 지금은 납품 초안만 필요해."
- "설정에 '내 데이터 다운로드'를 추가해 줘. PRD를 Figma에 써 줘: figma.com/design/<fileKey>, '설정' 영역에."
- "메시지 전송 취소 가능 시간은 얼마가 적당해? PRD에 넣어야 해."

## 우리 팀에 맞게 조정하기

- `references/design-system.md`: 팀의 디자인 라이브러리, 컴포넌트 키, 색상 및 타이포그래피 토큰(프로토타입 화면을 그릴 때만 사용).
- `references/rulings.md`: 팀의 작성 방식 결정 사항과 폐기된 레이아웃.
- `scripts/brand_terms.txt`: 카드 텍스트에 나오면 안 되는 브랜드 이름.
- SKILL.md의 "ZYMIX"와 "Box"는 각각 제품 이름과 의사결정자입니다. 필요에 따라 바꾸세요.
- Figma에 쓰려면 [figma-console MCP](https://github.com/southleft/figma-console-mcp)의 Desktop Bridge가 필요합니다. Markdown 초안만 만들 때는 추가로 필요한 것이 없습니다.
- SKILL.md에 언급된 `box-figma-prd`와 `box-prd-review`는 작성자의 비공개 보조 스킬(캔버스 점검과 전체 검토)입니다. 이것들이 없어도 생성 흐름은 동작합니다.

## 평가

중국어 에디션에서 실행했습니다.

- 블라인드 비교: 8개 시나리오(멀티 디바이스, 그룹 관리, 홍바오(red packet), 신고, 그룹 투표, 친구 피드, 신규 사용자 온보딩, 전송 취소/수정)에서 같은 요구사항으로 비슷한 스킬 21개와 비교했습니다. 출처를 모르는 Opus 심사자가 IM 정확성, 경계 사례 커버리지, 결정 처리, 구현 가능성, 가독성을 채점했습니다: 94라운드, 90승, 4패.
- 실제 트리거: 긍정 및 부정 프롬프트 31개 × 3회를 `claude -p`로 실행했습니다: 31/31 정확, 부정 프롬프트에서 오작동 없음.

기록: `zh-CN/box-prd-create/evals/trigger-results.md`. 영어 에디션은 별도로 평가하지 않았습니다.

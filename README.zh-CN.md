# im-prd-skill

[English](README.md) | [简体中文](README.zh-CN.md) | [繁體中文](README.zh-TW.md) | [日本語](README.ja.md) | [한국어](README.ko.md) | [Español](README.es.md) | [Português](README.pt.md) | [Français](README.fr.md)

一个写 IM／社交产品 PRD 的 Claude Agent Skill（技能包）。内置 26 个模块的主流即时通讯产品功能规则库，生成的功能默认符合 IM 惯例；只有主流产品做法不一致的点，才以选择题交给决策人裁决。可以只出 Markdown 交付稿，也可以把说明卡写到 Figma 画布上。

本技能原本为 ZYMIX 团队编写。公开版去掉了团队的 Figma 文件 key、设计系统取值、内部裁决和取证明细，流程、规则库、模板、脚本与评测用例完整保留。

## 解决什么问题

让 AI 直接写 IM 功能的 PRD，常见三个问题：

- 把拿不准的规则写得像定论。
- 只写正常流程，漏掉拉黑、注销、离线、多端、群聊与私聊差异这类异常状态。
- 行业惯例和团队真正要拍板的分歧混在一起，决策人只能通读全文去找。

本技能的做法：

- **规则库分三档**：
  - 基线：主流产品一致，默认遵循。
  - 惯例：多数产品这样做，按推荐默认。
  - 分歧点：各家做法不一，标「必问」或「可默认」。
- **只问必问题**：每次最多 4 道选择题，推荐项放第一个。其余按推荐写好，并在「已按推荐默认」里逐行列出，供决策人过目。
- **状态覆盖矩阵**：逐项检查成功、失败、超时、离线、权限、多端同步，以及对方已拉黑、已注销、已退群等状态。
- **不确定就标出来**：需要拍板的写 `{待定：议题，推荐：做法}`，缺事实源的写 `{待查：缺什么}`，不冒充定论。
- **写入闸门**：上 Figma 前一次性列出要新建的节点与批次，决策人同意后才写画布。

## 工作流

| 步骤 | 做什么 |
|---|---|
| 0 产品定型 | 确认会话形态（单聊／群／频道／社区）、端、是否端到端加密、陌生人是否可达，以及功能可行性前提 |
| 1 锁事实源 | 记录 Figma 文件与节点；需求逐项标「已定义／待确认／建议」 |
| 2 IM 规范对照 | 读命中的规则模块：基线照做，惯例按推荐，分歧点按级别处理 |
| 3 竞品参照 | 只有规则库没覆盖的新能力才做外部调研 |
| 4 状态覆盖矩阵 | 通用维度加模块必问状态，逐项标覆盖、不适用或未定义 |
| 5 先写交付稿 | 先写 Markdown 草稿，跑 `lint_card_text.py`；内容多时加一轮读者测试 |
| 6 排屏与编号 | 一次规划好屏序、行分组与编号 |
| 7 写入闸门 | `lint_card_text.py --gate` 通过且决策人同意后，才写画布 |
| 8 落卡与自检 | 每批写完自查，最后给验收回执 |

交付稿的固定顺序：

1. 待裁决
2. 已按推荐默认
3. 未决项
4. 角色视角速览
5. 说明卡
6. 功能清单
7. 验收要点（≤ 12 条）
8. 建议后续

## 安装

Claude Code 安装中文版（英文版把路径换成 `en/box-prd-create`）：

```bash
git clone https://github.com/ZBoxMan/im-prd-skill.git
```

```bash
cp -R im-prd-skill/zh-CN/box-prd-create ~/.claude/skills/
```

claude.ai：把 `box-prd-create` 目录打成 zip，在「设置 → 功能 → Skills」里上传。

## 使用

直接用自然语言提需求，例如：

- 「给群聊加群公告功能，写 PRD，先只出交付稿」
- 「设置页加『下载我的数据』，写 PRD 上 Figma：figma.com/design/<fileKey>，放在『设置』大区」
- 「撤回时限定多久合适？要写进 PRD」

## 接入你自己的团队

- `references/design-system.md`：填入你的设计系统库、组件 key 与颜色、字体 token。只在画原型屏时用。
- `references/rulings.md`：登记团队的写法裁决与已废弃版式。
- `scripts/brand_terms.txt`：说明卡里禁止出现的品牌名。
- SKILL.md 里的「ZYMIX」指产品名，「Box」指决策人，可按需替换。
- 上 Figma 依赖 [figma-console MCP](https://github.com/southleft/figma-console-mcp) 的 Desktop Bridge；只出 Markdown 交付稿时不需要。
- SKILL.md 提到的 `box-figma-prd`、`box-prd-review` 是作者的配套私有技能，分别用于画布取证和全量审核。没有它们也能完成生成流程。

## 评测

以下评测在中文版上进行：

- **盲评**：
  - 8 个场景：多设备、群管理、红包、举报、群投票、好友动态、新用户引导、撤回编辑。
  - 与 21 个同类 skill 用同一份需求对比。
  - 由 opus 在不知道来源的情况下按五个维度打分：IM 正确性、边界覆盖、决策处理、可实现性、可读性。
  - 累计 94 局，90 胜 4 负。
- **真实触发**：31 条正反例，每条用 `claude -p` 跑 3 次，31 条全部判对，负例零误触发。

记录见 `zh-CN/box-prd-create/evals/trigger-results.md`。英文版未单独评测。

## 规则来源与时效

- 采集于 2026 年 10 月。来源包括：
  - 主流 IM 客户端的公开行为
  - 开源客户端源码
  - 官方帮助中心与开发者文档
  - 协议规范
- 模块文件不含品牌名，各家取值明细未公开。
- 数值多为客户端默认值，服务端可能下发覆盖。建议每 90 天复核一次。

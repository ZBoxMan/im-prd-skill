# Message translation and in-chat AI (translation entry, auto-translate, AI invocation, AI labeling, privacy and encryption boundaries, failure and quota)

> Applies: read this file when the PRD involves message translation, auto-translate, translation language settings, invoking AI in a chat (summarize, ask AI, rewrite and polish), a standalone AI conversation entry, AI in groups, labeling of AI-generated content, and AI privacy notices. For the entry that switches the interface language itself see UI-37; for long-language and plural adaptation see UX-32 and UX-33. For the identity label when AI joins a group as a bot see BOT-03, and for the scope of group messages it can read see BOT-22. Evidence is in evidence/17-translate-ai.md.

## Baseline (follow by default, high confidence)
- **[AI-01] Entry for manually translating a single message**: a received text message offers "Translate" in the long-press menu, and tapping it gives the translation in place. Must define: the list of translatable objects (whether text, image captions, voice-to-text results, quoted original messages, and polls are each translatable); the entry display condition (whether it is hidden when the message is recognized as the target language or cannot be recognized); the source of the target language (see AI-06); the list of supported translation languages must cover at least all ZYMIX interface languages; the translation display form (see AI-18); whether the entry shows in encrypted chats (see AI-14). | Magnitude: not applicable | Confidence: High
- **[AI-02] AI processes only content the user actively submits**: when AI is invoked in a chat, only content the user actively submits (selecting, forwarding, @ invocation, dragging in, pasting) is handed to the AI, and the AI does not continuously read the whole chat. Must define: the content scope actually submitted by each entry (a single message, several selected messages, a whole stretch of unread, attached images or files); whether a "The following will be sent" confirmation is shown before submission (treat as must-ask, see AI-12); attachment count and type limits with over-limit copy (for reference: single digits); who in a group can invoke it and who sees the reply, see AI-16; for the read scope when AI joins a group as a member see BOT-22. | Magnitude: not applicable | Confidence: High
- **[AI-03] AI-generated content must be identifiable**: AI replies, summaries, and generated results carry a fixed label where displayed, stating they are AI-generated; in a conversation with AI it is made explicit that the other side is not a real person. Must define: the label copy and position (top of the content block, below the bubble, or beside the sender name); whether a prompt such as "For reference only" is added (for reference: one product); whether the label is kept after an AI result is copied, forwarded, or saved; the sender name and avatar of in-group AI messages; the feedback or report entry for AI results (for the report entry form see ACT-25); whether the message a user sends after adopting an AI rewrite is labeled to the recipient, see AI-17. | Magnitude: not applicable | Confidence: High

## Conventions (default-OK, mark as suggested)
- **[AI-04] Notice and consent before first use**: before first using an AI capability, show a usage notice and privacy statement, and the capability can be used only after the user agrees; before agreement the entry is visible but sends no request. Must define: the capability scope the notice covers (one consent for all AI capabilities, or consent per capability); the three things the notice must state: whether content leaves the device and to whom it is handed (see AI-12), whether it is used for training (see AI-13), and whether it can be deleted (see AI-10); where a refusal goes; whether re-consent is required after the notice is updated. | Magnitude: not applicable | Confidence: Medium (direct evidence from two products' clients; another product off by default and requiring active enablement is corroboration)
- **[AI-05] Translate only messages sent by others**: both manual and auto-translate act only on messages sent by others, and messages one sent oneself show no "Translate" and do not take part in auto-translate. Must define: whether forwarded-in messages from others, bots, and system messages are translatable; whether "translate while writing" before sending is offered is to be discussed separately (only one product offers it, for reference only, not in the first release). | Magnitude: not applicable | Confidence: Medium (direct evidence from two products)
- **[AI-06] Translation target language and interface language are set separately**: the translation target language is an independent setting, separate from the interface language; the target language defaults to the interface language. Must define: the location of the setting entry (for the interface language entry see UI-37); whether the target language follows when the interface language is switched (follows if never changed manually, does not follow once changed manually); whether switching the interface language takes effect immediately or needs a restart, and the prompt copy; whether the target language can be temporarily changed for a single translation. | Magnitude: not applicable | Confidence: Medium ("set separately" has direct evidence from two products; "defaults to the interface language" is from only one product, for reference only)
- **[AI-07] Translations and AI results state who processed them**: near a translation or AI result, state who provided it or how it was processed, with a tappable explanation entry. Must define: the attribution copy (such as "Translation provided by {provider}"); the explanation page content (where it is processed, whether it is retained, follows AI-12 and AI-13); the copy for on-device processing. | Magnitude: not applicable | Confidence: Medium (direct evidence from two products' clients)
- **[AI-08] Generation can be stopped**: while AI is generating, show an in-progress state and offer "Stop generating"; after stopping, keep the part already generated and allow regenerating. Must define: the in-progress copy; whether the part generated after stopping is marked "Stopped"; the "Regenerate" entry and whether the count counts toward the quota (see AI-22); whether generation continues when leaving the page. | Magnitude: not applicable | Confidence: Medium ("can be stopped" has direct evidence from two products; "regenerate" is from only one product, move it into must-define)
- **[AI-09] Failure and quota exhaustion have explicit prompts**: when a translation or AI request fails or the quota is exhausted, give a visible prompt and do not stay silent; failures can be retried. Must define: failure categories and their copy (network error, service busy, content not supported, account temporarily unavailable, no translation result, quota exhausted); for how to write quota-exhausted copy see SAFE-13, stating the recovery time; whether the input box draft and already submitted content are kept after failure. | Magnitude: not applicable | Confidence: Medium (direct evidence from two products; the sub-categories are each from only one product, move them into must-define)
- **[AI-10] Conversations with AI and associated memory can be deleted**: the user can delete a single item or a whole conversation with AI; when the AI has chat memory, deleting a conversation can also delete the related memory. Must define: the delete entry and confirmation copy; whether deletion also clears server-side retention and content already used for memory (data deletion scope, treat as must-ask); whether deletion syncs across devices; the entry to clear all AI records. | Magnitude: not applicable | Confidence: Medium (direct evidence from two products)
- **[AI-11] Writing assistance sits in the input bar, and results are adopted after user confirmation**: the entry for rewriting, polishing, and proofreading sits near the input bar; the result is previewed first, and the input box content is replaced only after the user selects "Adopt", "Keep editing", or "Discard", and it is never sent automatically. Must define: the available rewrite modes (see AI-23); whether the entry is hidden when the input is empty or too short; whether adoption can be undone back to the original; whether it is usable in encrypted chats (see AI-14). | Magnitude: not applicable | Confidence: Medium (direct evidence from two products)

## Divergences (ask Box on must-ask; write default-OK per recommendation and list it)
- **[AI-12] Where chat content handed to translation and AI services is processed**: Option A: server-side processing (may include a third-party provider), notice before first use and attribution at the result / Option B: on-device processing, content does not leave the device (translation is feasible, AI needs an on-device model, at the cost of language pack downloads and accuracy) / Option C: processing in a protected confidential-computing environment, declaring that neither the service operator nor third parties can read it. Recommended: follow SAFE-21: when one-on-one chats are end-to-end encrypted by default, choose B for translation and C for AI, or handle with A only when the user actively submits each time and state it each time; when encryption is only optional, regular chats use A. Rationale: privacy and data integrity first; no mainstream product hands end-to-end content to server-side processing when the user has not actively submitted it, and when the user actively submits each time (@AI, share), some products hand it to the server and state explicitly that the content is not protected by end-to-end encryption. | Level: Must-ask
- **[AI-13] Whether content submitted to AI is used to train or improve models**: Option A: not used for training, stated explicitly in the notice / Option B: usable for improvement by default (whether it can be turned off in settings is not evidenced) / Option C: not used by default, and the user can actively join an improvement program. Recommended: A. Rationale: privacy first; the only product that states it explicitly does B, so the recommendation is the opposite of it, a privacy tradeoff. | Level: Must-ask
- **[AI-14] Whether translation and AI can be used in encrypted chats**: Option A: not available, entry hidden or grayed out with the reason explained / Option B: only capabilities processed on-device are available (follows AI-12) / Option C: same as regular chats, content goes to the server. For the encryption scope see SAFE-21, and for other feature boundaries in encrypted chats see SAFE-22. Recommended: A, or B if AI-12 has chosen on-device. Rationale: privacy and data integrity; C would void the end-to-end promise, and no mainstream product opens auto-translate or whole-stretch outbound sending for encrypted chats. | Level: Must-ask
- **[AI-15] Chat-level disabling of AI**: Option A: not offered / Option B: chat settings offer "Do not allow AI in this chat", in a group enabled by the group owner and admins and in a one-on-one chat by either party, and once on, no member can submit this chat's messages to AI, with a system message left in the chat. Recommended: B. Rationale: when someone else's message is submitted to AI the sender has no way to know, a privacy matter of whether the other party can perceive and control it; only one product offers it, a privacy tradeoff. | Level: Must-ask
- **[AI-16] Who in a group can invoke AI and who sees the reply**: Option A: any member can invoke by @ in the group or by selecting messages to submit, and the reply is visible to the whole group / Option B: AI joins the group as a member, everyone receives a join system message, and admins can remove it (for the identity label see BOT-03) / Option C: no invocation in groups, messages can only be moved to a personal AI conversation. Which group messages the AI can read: see BOT-22 (for the scope of actively submitted content see AI-02) and is not asked again here. Recommended: A. Rationale: hands over only the content that is named, fewest states; B also requires deciding the read scope of BOT-22 separately. | Level: Must-ask | Framing: yes
- **[AI-17] Whether the message a user sends after adopting an AI rewrite is labeled to the recipient**: Option A: not labeled, sent in the user's own name after the user confirms / Option B: labeled "AI-assisted writing", cannot be turned off / Option C: labeled by default, and the sender can turn it off. Recommended: A. Rationale: the user has reviewed it and is responsible for the content, and neither product's writing assistance labels it to the recipient; switch to B when target-market regulation requires labeling AI-generated content. | Level: Must-ask
- **[AI-18] Translation display form**: Option A: the original is kept, and the translation is attached below the original with a "Translation" label, collapsible / Option B: the translation replaces the original, with a "Show original" toggle. Recommended: A. Rationale: user understanding: the original and translation are visible together, so no one mistakes it for the other party having sent in their language; the only direct evidence is B, so the recommendation is the opposite, a user-understanding tradeoff. | Level: Default-OK
- **[AI-19] Granularity for turning on auto-translate**: Option A: offer only manual single-message translation / Option B: turn on auto-translate per chat, off by default, and messages received afterward are translated automatically / Option C: a global switch, and once on all chats are auto-translated. Recommended: B. Rationale: recoverable and with a controllable impact surface, two products do it per chat; the outbound scope follows AI-12. | Level: Default-OK
- **[AI-20] Whether to proactively prompt to turn on translation**: Option A: no proactive prompt, offered only in the long-press menu and chat settings / Option B: when this device recognizes that foreign-language messages make up the majority in a chat, show a "Translate to {language}" prompt bar at the top of the chat, which can be dismissed, and once dismissed it is no longer shown on any device. Recommended: A. Rationale: fewer states and misjudgments in the first release; only one product prompts proactively, and its documented threshold is inconsistent with its implementation. | Level: Default-OK
- **[AI-21] List of languages not to translate**: Option A: no list, and messages in the same language as the target language show no translate entry / Option B: offer a list, defaulting to the interface language and system language, which the user can add to and remove from. Recommended: A. Rationale: when there are few interface languages, a single target language is enough to decide; only one product offers a list. | Level: Default-OK
- **[AI-22] Quota and paid tiers for translation and AI**: Option A: no paid tier, the server sets a daily quota per account, restored the next day after it runs out / Option B: single-message translation is free, and ongoing capabilities such as auto-translate and format preservation are paid / Option C: no quota. Recommended: A. Rationale: prevents abuse without introducing a payment flow; free single-message translation is the consensus, and only one product has a paid tier. | Level: Default-OK
- **[AI-23] Rewrite modes for writing assistance**: Option A: a few fixed tones (such as formal, friendly, concise) plus proofreading / Option B: fixed tones plus user-defined descriptions, with custom styles that can be saved and shared. Recommended: A. Rationale: easy to implement with predictable results; custom and sharing are from only one product. | Level: Default-OK
- **[AI-24] Form of the standalone AI conversation entry**: Option A: a standalone bottom tab / Option B: a pinned AI contact in the chat list / Option C: merged with the search bar. Recommended: follow existing ZYMIX rules (there is already an AI tab). Rationale: consistency. | Level: Default-OK
- **[AI-25] Incognito AI conversations**: Option A: not offered / Option B: offer an incognito mode that disappears on exit, cannot be recovered, and does not enter memory. Recommended: A. Rationale: fewer states in the first release; only one product offers it. | Level: Default-OK

## Must-ask states (specific to this module, supplementing the general state matrix)
- Translation objects: how the translate entry and an already shown translation are each handled when the message has been unsent, has been edited, is a time-limited message that has expired, is a pure emoji or pure link, has an unrecognizable language, or is already in the target language.
- Translation lifecycle: whether the translation becomes invalid and is retranslated after the original message is edited; whether the translation disappears together with it after an unsend; whether existing translations are retranslated after the target language is switched; whether the translation is kept after leaving and reentering the chat.
- Auto-translate: whether historical messages are back-translated after it is turned on; whether several consecutive messages from the other party are batched; how auto-translate stops and prompts when a chat changes from regular to encrypted.
- Multi-device: whether the auto-translate switch, "Don't remind again", the AI notice consent state, and AI conversation records each sync across devices.
- AI generation: switching to the background, going offline, or leaving the chat during generation; regenerating after stopping; whether sources can be viewed and reported when a generated result contains links or sources.
- AI in groups: the invoker being muted or leaving the group; the submitted message being unsent afterward; a request in progress when chat-level AI disabling is turned on; the label when an AI reply is quoted or forwarded by other members.
- Privacy: whether the original sender of a submitted message can know their message was handed to AI; whether I can submit the historical messages of someone who has blocked me to AI.
- Quota and availability: how auto-translate degrades when the quota runs out; whether the entry is hidden or prompts on tap when the account or region is unavailable.

## Anti-patterns
| Vague or wrong | Correct | Reason |
|---|---|---|
| "Supports message translation" | Write the entry location, translatable objects, source of the target language, translation form, and failure and quota copy | Translation involves three kinds of branches: object, language, and network |
| "AI will read the chat content to help you answer" | Write the content scope each entry submits, where it is processed, and whether it is used for training | An unclear read scope is a privacy incident |
| AI replies displayed the same as real people's messages | AI results carry a fixed label, and whether the label stays after copy and forward is defined separately | Users cannot tell AI from real people |
| Encrypted chats do not mention translation and AI | State whether the entry is usable in encrypted chats and the reason copy | Handling them by default as regular chats would void the end-to-end promise |
| "Auto-translate all messages" | Write the granularity for turning it on, the default, translating only others' messages, and whether history is back-translated | Global automatic outbound sending amplifies the privacy impact |
| The rewrite result is sent directly | Preview, then the user adopts, keeps editing, or discards | The user must be responsible for what is sent |
| "Translation failed, please retry" dismissed in one line | Write copy and recovery time separately for network, busy, no result, and quota exhausted | Cannot be accepted |

## Calibration sample
The feature most easily written vaguely: long-press to translate a single message. Premise of this sample: the product has optional encryption and regular chats are not end-to-end, and the recommendation of "server-side translation" in item 2 holds only under this premise; when one-on-one chats are end-to-end by default, rewrite it as on-device translation. Tapping has three preconditions, quota, first-use notice, and network, so start a decision chain; rate limits such as quota go in the first step, and none of the three depend on a server response. The entry display condition, source of the target language, translating only others' messages, translation form, and failure and quota copy are written as body text per recommendation, with values illustrative; whether content is sent to the server for processing and whether encrypted chats can use it fall in the privacy scope and are must-ask, so leave placeholders in the card.

Description:
1. Entry: long-press a text message sent by someone else; when the message language differs from the translation target language or cannot be recognized, the menu shows "Translate"; it is not shown for messages in the same language as the target language, messages one sent oneself, and system messages
2. On tap, check in order:
   a. 1-Quota check: whether today's translation count has reached 200, counted by the calendar day in the account's time zone and reset at 00:00
      i. Limit reached: toast prompt: "Today's translations are used up, restored after 00:00 tomorrow", stay in the chat, no translation
      i. Limit not reached: go to the next check
   a. 2-Notice check: whether this account has agreed to the translation notice
      i. Not agreed: dialog showing the translation notice, {TBD: whether message content is sent to the server for translation, recommended: server-side translation, with the notice stating it is not used for training}; tapping "Agree" goes to the next check, tapping "Cancel" closes the dialog, stays in the chat, no translation
      i. Agreed: go to the next check
   a. 3-Network check: whether there is a network now
      i. No network: toast prompt: "Network unavailable, check your network and try again", stay in the chat
      i. Has network: "Translating…" is shown below the original, and translation starts
3. In encrypted chats {TBD: whether translation can be used in encrypted chats, recommended: the menu does not show "Translate"}
4. Translation succeeds: the original is kept, the translation is shown below the original with the "Translation" label; long-pressing the translation offers "Copy translation" / "Collapse translation"
5. Translation has no result: the translation position shows "No translation result"; service busy: shows "Translation failed, tap to retry", and tapping restarts it
6. The target language defaults to the same as the interface language (English/简体中文/Tiếng Việt/Filipino), and can be changed separately in "Settings - General - Language"
Note: whether content is sent to the server for translation and whether encrypted chats can use translation are finalized after confirmation

## 事实源与管辖

**事实源**：`<设计系统库名>`（libraryKey `<libraryKey>`）。写明它是独立发布库还是 PRD 文件内的页面，以及库里有没有 Figma 变量与样式；没有变量时画屏直接写色值，不要写 `setBoundVariable`。

**管辖边界**：只管原型帧内的界面内容。标注层不受约束，说明卡正文按 SKILL.md「说明卡正文不写视觉规格」处理。

## 组件怎么用

在 `figma_execute` 脚本里用 `importComponentSetByKeyAsync(key)` / `importComponentByKeyAsync(key)` 按 key 导入，再 `createInstance()`。**组件导入需要决策人单独授权**，与 Figma 写入授权是两回事。库里存在同名组件集多份时，按宽度和变体数认当前版，不按时间戳。

| 组件 | componentKey | 规格 |
|---|---|---|
| 会话列表行 | `<key>` | `<宽×高，变体>` |
| Tab 栏（浅色） | `<key>` | `<宽×高，变体>` |
| Tab 栏（深色） | `<key>` | `<宽×高，变体>` |

库里没有宽度匹配的组件时自绘，并在这里登记。

## 颜色 token

按语义选 token，不按色值反查；同值不同语义的 token 要分别登记。

| Token | 色值 | 使用场景 |
|---|---|---|
| `<A1>` | `<#RRGGBB>` | `<品牌主色、主按钮、选中状态>` |

把已知的对比度缺陷（如主按钮文字对比度不足）登记在表下，PRD 侧沿用不改，但要说明。

## 字体 token

| Token | 字体 / 字号 / 行高 / 字重 | 使用场景 |
|---|---|---|
| `<Body_S_500>` | `<字体 14/20 500>` | `<正文>` |

## 深色调

写明深色模式的取值来源（独立 token 还是同名 token 的深色值）；没有定义的不要反推新 token。

## 叠件规格（画屏用）

Toast、行内错误、弹窗、底部面板等叠件各写一行：用哪些颜色与字体 token、位置与层级。与 token 表冲突时以 token 表为准，并登记到 `rulings.md`。

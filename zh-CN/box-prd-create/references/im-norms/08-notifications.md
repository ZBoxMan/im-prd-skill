# 通知（推送、免打扰穿透、角标）

> 适用：推送预览、通知设置页、免打扰与 @提及/回复穿透、角标计数、多端推送、来电与未接来电通知的 PRD 需求。会话列表上的免打扰标识与未读呈现参见 03-chat-list.md。证据见 evidence/08-notifications.md。

## 基线（默认遵循，置信度高）
- **[NOTI-01] 通知设置分层**：全局总开关与提示音开关 + 单会话例外（可覆盖全局）。必定义：总开关关闭时子项是否置灰；单会话例外入口；是否提供一键恢复默认，及其确认文案与影响范围（是否清除各会话的自定义）。｜量级：—｜置信度：高
- **[NOTI-03] 预览控制**：提供「通知里是否显示消息内容」的控制，且存在「不显示内容」的档位；不显示内容时通知只显示会话名或通用文案。必定义：档位数量与文案（见 NOTI-23）；作用范围（全局、按会话类型、单会话）；锁屏与解锁状态是否区别对待。｜量级：两档至三档｜置信度：高
- **[NOTI-04] 免打扰期间默认静默**：不弹通知、不响铃、不震动；消息照常入库，未读照常累计。必定义：被静默期间产生的通知，到期后是否补发。｜量级：—｜置信度：高
- **[NOTI-07] 角标可控且口径显式**：角标计数为未读汇总，口径显式写明；用户可关闭角标。必定义：计数单位（见 NOTI-25）；免打扰会话是否计入见 NOTI-26；计入的会话类型（会话列表广告条目是否计入见 ADS-07）；超过阈值的截断。｜量级：—｜置信度：高

## 惯例（可默认，标建议）

- **[NOTI-05] @提及穿透可配置**：免打扰下被 @我 的消息是否仍通知，由用户设置项决定，不写死；开关默认值见 NOTI-20。必定义：被 @ 的通知是否使用独立于普通消息的文案及文案内容；@全体 是否同开关（见 NOTI-21）；回复是否同开关（见 NOTI-22）。｜量级：—｜置信度：中（两家直接证据为可配置；一家被提及固定穿透群静音、不可单独关闭，为反例）
- **[NOTI-02] 按会话类型分设**：至少区分单聊与群聊的通知偏好（是否提醒、预览、弹窗）。必定义：分设的维度；群聊设置是否覆盖到所有群；新建会话的初始继承。｜量级：—｜置信度：中（两家直接证据，另一家偏弱）
- **[NOTI-08] 来电提示独立于消息提示**：来电有独立于消息的提示音设置；未接来电在会话中留一条通话记录系统消息，可随时追溯，不因免打扰或专注期而丢失记录。必定义：通话提示音入口；未接记录文案（见 MISC-04）；免打扰会话来电与群单独静音来电见 NOTI-30。｜量级：—｜置信度：中（两个子句各有两家直接证据）
- **[NOTI-06] 时长型免打扰到期自动恢复**：按时长设置的免打扰到点自动恢复通知，无需用户操作。必定义：到期前是否提示；到期瞬间已有未读的通知处理。｜量级：—｜置信度：中（两家直接证据，另一家为档位语义推断）

## 分歧点（必问的问 Box，可默认的按推荐写并列清单）
- **[NOTI-20] @我 穿透的默认值**：选项 A：默认不穿透，需用户开启「@我时仍通知」／选项 B：默认穿透，用户可关闭。推荐：A，理由：用户理解——「免打扰」的字面含义就是不被打扰，穿透由用户主动选择。取舍背景：默认值各家不一（一家默认穿透，两家默认不穿透）。｜级别：可默认
- **[NOTI-21] @全体 是否穿透**：仅一家有直接证据（接收方可单独静音 @全体、保留 @我 的穿透），其余产品只见独立标识与文案。选项 A：不穿透，仅在列表有独立 @ 标识／选项 B：穿透／选项 C：与 @我 分开设独立开关，默认关闭。推荐：C，理由：用户理解——@全体 易被滥用，用户应能单独决定，且已有产品提供该独立开关。｜级别：可默认
- **[NOTI-22] 回复是否穿透**：被回复（引用了我的消息）时。选项 A：与 @提及 同一开关（「仅提及和回复」）／选项 B：不穿透，仅 @。推荐：A，理由：用户理解——两者都是「指向我的消息」，合并开关更易懂；现有两家直接证据都让被回复与被提及同样穿透。｜级别：可默认
- **[NOTI-23] 预览档位数**：选项 A：两档（显示内容／不显示内容，会话名仍显示）／选项 B：三档（显示名称与内容／仅名称／名称与内容都不显示）／选项 C：两档加独立的「通知显示详情」开关。推荐：B，理由：隐私与数据完整——需要覆盖「连会话名都不想在锁屏出现」的场景。｜级别：可默认
- **[NOTI-24] 陌生人请求与一次性内容的通知**：选项 A：陌生人消息统一显示「消息请求」且不展示正文；一次性内容用类型占位／选项 B：与普通消息一致。推荐：A，理由：隐私——用户尚未接受的对象不应通过通知预览出正文。｜级别：必问
- **[NOTI-25] 角标计数单位**：选项 A：未读消息数／选项 B：未读会话数／选项 C：用户可切换。推荐：C，理由：用户理解——两种口径各有人用，且有直接证据支持可切换。｜级别：可默认
- **[NOTI-26] 免打扰会话与角标**：选项 A：默认不计入，可在设置开启「包含免打扰会话」／选项 B：计入，但与普通会话以不同状态区分／选项 C：始终计入。推荐：A，理由：用户理解——免打扰会话不应推高角标制造焦虑。｜级别：可默认
- **[NOTI-27] 多端推送抑制**：本轮对其语义只取到配置字段名（低置信度）。选项 A：任一设备正在使用该账号时，延迟或不向其他设备推送／选项 B：各设备独立推送／选项 C：A 的基础上增加「App 在前台时是否仍弹通知」开关。推荐：A，理由：用户理解——避免已在看的设备外还被其他设备重复提醒。采用 A 时「正在使用」须写成可测口径：窗口在前台且最近数分钟内有操作；只看窗口未最小化会让离开电脑的用户在手机上漏掉消息。｜级别：可默认
- **[NOTI-28] 通知合并**：本轮未取到各产品的合并规则（未取证）。选项 A：同一会话的多条通知合并为一条并累计「{n} 条新消息」／选项 B：逐条显示。推荐：A，理由：用户理解——避免锁屏被同一会话刷屏。｜级别：可默认
- **[NOTI-29] 通知配置（专注模式）**：选项 A：不做／选项 B：可命名的通知配置，设定期间允许的会话与是否允许 @提及（名称长度量级数十个字符）。推荐：A，理由：用户理解——仅一家有直接证据，且与免打扰档位职责重叠。｜级别：可默认
- **[NOTI-30] 免打扰会话来电**：选项 A：来电不受会话免打扰影响，仍响铃（仍受系统勿扰约束）／选项 B：受影响，仅留未接记录／选项 C：消息静音与来电静音分设两个开关（群内可单独静音来电），默认来电仍响铃。推荐：A，理由：无障碍与可恢复——来电有时效，静默后无法补救；选项 C 仅一家有直接证据，属 A 的扩展。｜级别：可默认
- **[NOTI-31] 特别关注成员穿透**：选项 A：不做／选项 B：群内可把指定成员设为「特别关注」，其发言穿透免打扰，取消后恢复。推荐：A，理由：用户理解——仅一家有直接证据，且与 @提及 穿透功能重叠。｜级别：可默认
- **[NOTI-32] 回应（表情反应）通知**：选项 A：不通知／选项 B：通知，可单独关闭，预览可单独控制。推荐：B，理由：用户理解——对自己消息的回应属于有意义的反馈，但须可关。｜级别：可默认
- **[NOTI-33] 受保护会话的通知占位**（仅在做「锁定会话」时适用，见 03-chat-list.md 的 LIST-31）：选项 A：锁定会话的通知只显示通用文案（{应用名}，或「{应用名}：1 条新消息」），不显示发送者与内容／选项 B：沿用全局预览档位。推荐：A，理由：隐私——锁定的目的是不暴露会话存在与内容，通知预览会让锁定失效；仅一家有直接证据。｜级别：可默认

## 必问状态（本模块专属，补充通用状态矩阵）
- 对方已拉黑/已注销：被拉黑后其发来的内容是否仍产生通知；注销后已展示的通知是否保留。
- 已退群或被移出群：该群已排队的通知是否清除；@我 的通知是否保留。
- 已归档或已静音会话被 @我 或被回复：是否仍通知、是否回到主列表、列表是否显示 @。
- 多端：另一台设备已读后，本机已展示的通知是否自动清除；一台设备改了免打扰，其他设备何时生效（已知一家的免打扰设置不同步到关联设备，桌面端仍弹通知）。
- 离线接收方：离线期间累计的通知，恢复在线后是合并展示还是逐条补发；推送延迟超过多久视为过期。
- 消息已撤回或已被编辑：通知已展示后，通知内容是否同步更新或移除。
- 通知权限被系统关闭或在使用中被收回：设置页的呈现与引导；应用内是否仍有未读提示。
- 锁屏与解锁：预览档位是否区分锁屏与解锁状态；多账号时通知是否标明账号。
- 群与单聊差异：同一人在单聊与群里分别发消息，免打扰各自生效；被 @ 时已处于免打扰到期前一刻。
- 弱网：推送到达但拉取消息失败时，通知文案与点击后的去向。
- 通话中收到新消息：消息通知是否降级为不响铃。
- 锁定会话（若选 NOTI-33）：锁屏与解锁后通知显示什么；锁定会话的来电通知是否同样隐藏。

## 反模式
| 泛写/错写 | 正写 | 原因 |
|---|---|---|
| 「免打扰后收不到通知」 | 写清免打扰期间的静默项（弹窗、响铃、震动、角标）与穿透项（@我、回复、来电） | 穿透与否是用户最常投诉的点 |
| 「角标显示未读数」 | 写计数单位、免打扰是否计入、会话类型范围、截断阈值 | 口径不明，角标与列表对不上 |
| 「通知显示消息内容」 | 写预览档位、作用范围、锁屏与解锁差异、陌生人与一次性内容的占位 | 隐私泄露面不清 |
| 「被 @ 时通知」 | 写开关默认值、@全体 与回复是否同开关、独立文案 | 与免打扰的优先级冲突 |
| 「多端同步通知」 | 写已读后通知清除、抑制规则、各设备独立设置的边界 | 多端重复提醒 |
| 「来电时响铃」 | 写与消息免打扰的关系、未接记录、权限被收回的回退 | 漏接无法补救 |
| 「点击通知进入会话」 | 写会话已删除、已退群、已被归档、账号已退出时的去向 | 点击后落点未定义 |

## 校准样例
最易写泛的功能：免打扰群聊里的「@我时仍通知」开关。以下为一张合格说明卡正文（点击开关前没有需要校验的条件，不起判断链）。本例没有必问项：开关默认值、@全体 与回复是否同开关、多端同步都按推荐写成正文，并在交付稿「已按推荐默认」逐条列出。

说明：
1. 展示条件：群聊开启免打扰后，群聊设置中展示开关「@我时仍通知」；未开启免打扰的群聊与单聊不展示该开关
2. 默认状态：关闭
3. 点击开关即在开启/关闭之间切换，本机立即生效，并同步到本账号已登录的所有设备
4. 开启时：免打扰期间被 @我 或被回复（引用了我的消息）的消息仍推送通知，文案「{发送者} 在群聊中@了你」或「{发送者} 回复了你」；其他消息仍静默
5. 关闭时：被 @我 与被回复的消息与其他消息一样静默；会话列表仍显示 @ 标识，未读照常累计
6. 被 @全体 的消息不受此开关控制，由同页「@全体成员时仍通知」开关单独控制，该开关默认关闭
7. 关闭免打扰后此开关隐藏；再次开启免打扰时恢复上次的开关状态

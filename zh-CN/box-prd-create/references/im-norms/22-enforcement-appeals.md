# 账号与群的处罚与申诉（处置梯度、受限提示、申诉、结果与恢复、原因披露）

> 适用：PRD 涉及平台对账号或群的处置（功能受限、冻结、封禁、群被停用），以及受限提示与解除时间、点击受限功能时的拦截、申诉入口与状态、申诉结果通知、处罚期间与误封恢复后的数据、对被处罚者披露原因时读本文件。账号受限的总则见 ACC-11；群内管理员禁言见 GRP-23，移出并禁止再入见 GRP-25；举报见 09 模块（SAFE-09 至 SAFE-12、SAFE-29）；频控提示见 SAFE-13；钱包冻结见 WAL-21、WAL-22；频道被封禁见 FEED-13；发送被阻止的文案见 SEND-06。各地区法规对处罚通知内容、申诉期限与人工复核的硬要求，一律写「按上架地区合规要求」，本文件不给数值。证据见 evidence/22-enforcement-appeals.md。

## 基线（默认遵循，置信度高）
- **[ENF-01] 处置分级：功能受限与整号封禁分开**：平台处置至少分「部分功能受限」与「整号封禁」两级，不把所有违规都直接封号；功能受限优先收紧面向新对象的发起类动作（加好友、向非好友发起会话、建群或拉人入群）。必定义：采用哪几级（警告、内容处置、功能受限、冻结只读、临时封禁、永久封禁）及每级受限的能力清单与仍可使用的能力；功能受限期间能否与已有好友和已加入的群照常沟通；受限是否连带登出其他已登录设备；累犯加重的升级条件；是否连带处置同一人的关联账号；永久处置的告知文案。解除时间展示见 ENF-07。｜量级：首次功能受限多为天级，累犯加长直至永久｜置信度：高
- **[ENF-02] 申诉入口在处罚提示内直达**：处罚提示（冻结横幅与详情页、封禁页、打开应用时的拦截页）内直接提供申诉入口。必定义：入口文案与位置；整号封禁、无法进入主界面时从哪里发起申诉（可参考：从封禁页发起，两家直接证据）；哪些处罚可申诉见 ENF-09，不可申诉时页面如何说明；申诉形态见 ENF-10；是否只能在客户端内发起，还是另有网页或客服渠道；复核是否须人工参与、申诉期限多长，按上架地区合规要求。｜量级：不适用｜置信度：高

## 惯例（可默认，标建议）
- **[ENF-03] 点击受限功能时就地拦截并说明**：功能受限期间点击被限制的动作（发起新会话、加好友、建群、拉人入群），当场提示该功能受限并给出详情入口，不静默失败，不让操作看似成功。必定义：每个受限动作的提示文案与载体；入口保留可点（便于说明）还是置灰；提示是否带解除时间（见 ENF-07）；发送类受限的文案与输入栏形态见 SEND-06、UI-D7。｜量级：不适用｜置信度：中（两家直接证据）
- **[ENF-04] 有期限的受限到期自动解除**：有期限的功能受限到期后自动恢复，不需要用户申诉或任何操作。必定义：解除的判定口径（以服务端处置记录的解除时间为准）；解除时是否通知本人及载体（通知载体见 ENF-13）；离线期间到期，上线后的状态刷新；受限期间再次违规是重新计时还是升级。｜量级：不适用｜置信度：中（两家直接证据）
- **[ENF-05] 平台对群的处置与对成员账号的处置分开**：群被平台停用（暂停或永久）不连带普通成员的账号受限；对单个成员的处置只影响该成员，其他成员不受影响。必定义：群级处置的级别（限制部分群功能、暂停群聊、永久停用、解散）；群主与管理员在什么条件下连带受罚（一种做法：明知违规不制止时连带）；群停用通知与群主个人处置通知是否分开发；群主对群停用的申诉入口（见 ENF-02）；成员视角见 ENF-17；频道被封禁见 FEED-13。｜量级：不适用｜置信度：中（两家直接证据）
- **[ENF-18] 群内被管理员禁言**：见 GRP-23（群管理员对成员的个人禁言；被移出并禁止再入见 GRP-25）。本模块只管平台对账号与群的处置。
- **[ENF-19] 举报入口与形态**：见 SAFE-09（举报对象覆盖见 SAFE-11，举报反馈见 SAFE-12，举报后的后续动作见 SAFE-29）。
- **[ENF-20] 钱包被冻结或受限**：见 WAL-21（对本人披露什么；付款方视角见 WAL-22）。账号处罚连带钱包时，钱包侧的原因披露按 WAL-21，不按 ENF-08。
- **[ENF-21] 短时频控触达**：见 SAFE-13（操作过于频繁的限流提示，不属于账号处罚，不进入处罚详情与申诉流程）。

## 分歧点（必问的问 Box，可默认的按推荐写并列清单）
- **[ENF-06] 受限状态的告知载体**：选项 A：会话列表顶部常驻横幅，点击进入处罚详情页（类型、受限范围、仍可使用的功能、解除时间、原因、申诉）／选项 B：不设常驻提示，只在点击受限功能时提示（拦截见 ENF-03）／选项 C：打开应用时先显示拦截页，确认后进入。推荐：A，整号封禁无法进入主界面时改用 C 承载详情与申诉，理由：用户能理解当前状态，随时可查期限与申诉入口；三种做法各有产品采用。｜级别：可默认
- **[ENF-07] 解除时间是否展示**：选项 A：详情页与拦截提示都写明解除时间（日期与时刻，按账号所在时区，见 UX-36），永久处置写明「永久」／选项 B：只在详情页写，拦截提示只说「暂时受限」／选项 C：不写时长，只给「短期」「暂时」一类定性描述。推荐：A，理由：用户能理解当前状态，减少反复试探与咨询；与多数产品做法相反（两家露出时间、三家只给定性描述或不披露），属用户理解优先取舍。｜级别：可默认
- **[ENF-08] 对被处罚者披露原因与依据的程度**：选项 A：只说「违反平台规则」，不写具体原因／选项 B：写明原因类别（如垃圾信息、诈骗、骚扰、冒充）、依据的规则条款、处置类型与期限、是否由系统自动判定、可用的申诉与其他救济途径，不附被处置的具体内容／选项 C：在 B 基础上附被处置的具体内容（消息、帖子或群名）。三个选项都不披露举报人身份。推荐：B，具体披露项按上架地区合规要求取齐，理由：用户能理解为何受罚并据此申诉；与现有产品做法相反（已知产品都只给「违反条款」一级的说明），属合规与用户理解优先取舍。级别理由：选 C 会把他人发出的消息或群名展示给被处置者，属 ①；钱包冻结的原因类别受持牌机构合规约束、以其答复为准，Box 可取舍的部分小，故 WAL-21 为可默认，两者在 ENF-20 分开归属。｜级别：必问
- **[ENF-09] 哪些处罚可以申诉**：选项 A：所有处罚都可申诉，含有期限的功能受限／选项 B：只有封禁与永久处置可申诉，有期限的受限等待到期／选项 C：在 A 或 B 基础上，部分严重违规为终局、不可申诉。推荐：A，理由：可恢复，误判的受限也有救济；部分上架地区要求对功能受限、账号暂停与终止都提供申诉渠道。｜级别：可默认
- **[ENF-10] 申诉形态**：选项 A：一键「申请复核」，可选填申诉说明／选项 B：表单，选择申诉理由、填写说明、可附图片／选项 C：身份验证后自助解除（短信验证或好友辅助验证）。推荐：A，因账号安全异常（疑似被盗）导致的冻结另提供 C，理由：用户理解成本最低；自助解除只适用于不涉及违规判定的安全冻结。状态机见 SUP-10。｜级别：可默认
- **[ENF-11] 申诉次数与状态**：申诉状态为审核中、已通过、已驳回、已过期四种，审核中不可重复提交。选项 A：每次处罚只能申诉一次，驳回即终局／选项 B：驳回后可补充材料再申诉一次，再驳回为终局／选项 C：不限次数，两次之间设冷却。推荐：B，理由：可恢复，首次材料不足导致的维持仍有一次补救，又不让申诉被反复刷。状态机见 SUP-10。｜级别：可默认
- **[ENF-12] 申诉处理时长是否承诺**：选项 A：提交后写明预计处理时长（如「通常在 {N} 个工作日内处理」；承诺口径见 SUP-13：服务端受理时间起算、按工作日计、需补充期间暂停计时）／选项 B：不承诺时长，只说「已提交，审核后通知你」。推荐：A，理由：用户能理解当前状态，减少重复提交；一家产品给出时长承诺。时长取值取决于审核运营能力，属事实源缺口，写 {待查} 进未决项。状态机见 SUP-10。｜级别：可默认
- **[ENF-13] 申诉结果与到期解除的通知载体**：选项 A：在平台系统会话发一条并推送（系统会话形态见 BOT-09），处罚详情页状态同步更新；驳回时附后续救济途径（按上架地区合规要求）／选项 B：只更新详情页状态，不主动通知／选项 C：短信或邮件。推荐：A，理由：结果是用户在等的事项，主动通知且留痕可回看；整号封禁无法登录时，结果显示在下次打开的封禁页。状态机见 SUP-10。｜级别：可默认
- **[ENF-14] 处罚与申诉期间的数据保留与本人访问**：选项 A：处罚期间本人可只读登录（查看历史与导出，不能发送与操作），数据完整保留；申诉期满或终局后只关闭申诉入口，不因处罚删除数据／选项 B：处罚期间本人不可访问，数据完整保留，解封后恢复访问／选项 C：设申诉截止日并在处罚提示中明示，逾期未申诉或终局驳回后删除账号与全部数据。申诉期长度按上架地区合规要求。推荐：A，理由：隐私与数据完整优先，本人数据不因尚未定论的处罚而不可达或被删除；删除只走注销、长期不活跃与低龄账号处置（见 ACC-22、AGE-11）。处罚期间的积分与会员剩余期见 PTS-22。｜级别：必问
- **[ENF-15] 误封恢复后的数据与关系**：选项 A：完整恢复，账号、联系人、群成员身份与因处罚被移除的内容全部恢复，处罚期间他人发来的消息在离线保留期内补送，超出保留期的在恢复通知里说明／选项 B：恢复账号与历史消息，因处罚被移出的群与被删除的内容不恢复／选项 C：只恢复登录能力，其余由用户自行重建。推荐：A，理由：误封是平台的错误，数据完整与可恢复优先；群已解散的不恢复，期间已有新群主的恢复为普通成员。｜级别：必问
- **[ENF-16] 被处罚账号在他人侧的呈现**：选项 A：功能受限对他人不可感知；整号封禁期间他人看到中性的「该账号暂时无法使用」，不提违规；永久封禁与注销账号呈现一致／选项 B：受限与封禁对他人都不可感知，消息照常显示已发送、实际不投递／选项 C：明示「该账号因违规被封禁」。推荐：A，理由：处罚是本人敏感状态，不应暴露给他人；B 让他人的消息静默丢失，破坏数据完整。｜级别：必问
- **[ENF-17] 群被平台停用后成员的会话与历史**：选项 A：会话保留为只读，顶部说明「该群已停用」，历史消息与群文件可查看，不写停用原因与群主信息／选项 B：会话保留只读，历史消息可看，群文件与媒体不可再下载／选项 C：会话移除，邀请链接与搜索显示与群不存在相同。推荐：A，理由：成员的历史数据不因群被处置而丢失，用户能理解群为何不可用；停用原因只告知群主（披露程度见 ENF-08）。｜级别：必问

## 必问状态（本模块专属，补充通用状态矩阵）
- 处置生效瞬间：正在发送的消息、进行中的通话、编辑中的草稿、处理中的付款（钱包侧见 WAL-21）；离线时被处置，上线后先看到什么。
- 多端：一台设备上看到受限时其他已登录设备是否同步；处置期间新设备登录；受限是否连带登出关联设备。
- 群身份：被处置者是群主或管理员时群的管理权；处置期间被移出的群、群已解散或已转让；恢复后能否回到原群（见 ENF-15）。
- 处置叠加与变化：受限中又被封禁；申诉审核中处罚到期自动解除；两台设备同时提交申诉；申诉中注销账号；申诉通过后的生效时点与多端刷新；申诉的状态流转与通知见 SUP-10。
- 号码回收：新机主注册的号码前任有处罚记录；被封账号的号码在处罚期内能否注册新账号或换绑。
- 他人视角：对方受限或被封时我给他发消息、加他好友、拉他入群看到什么（呈现见 ENF-16）；被封者是我所在群的群主。
- 群与频道被停用：成员离线期间群被停用；群内进行中的通话或实时位置共享；频道被封禁见 FEED-13；服务号被封禁见 13 模块必问状态「服务号侧异常」行。
- 恢复：误封恢复后是否需重新验证身份；处罚期间未送达的消息；恢复后处罚详情页与系统会话里的记录如何显示。
- 地区差异：处罚通知字段、申诉期限、复核是否须人工参与按上架地区合规要求，不同地区用户看到的详情页字段是否一致。

## 反模式
| 泛写/错写 | 正写 | 原因 |
|---|---|---|
| 「账号已被限制」后无下文 | 写清级别、受限范围、仍可使用的功能、解除时间或永久、原因、申诉入口 | 用户不知道能做什么，只会反复试探与咨询客服 |
| 受限功能点击后无反应或看似成功 | 就地拦截并说明受限，给详情入口 | 静默失败让用户以为对方不回复或网络故障 |
| 申诉只画一个「提交申诉」按钮 | 写申诉资格、重复提交、审核中状态、结果通知、驳回后去向、申诉期限 | 申诉是有状态的流程，缺分支就无法实现 |
| 「封禁后清除数据」 | 写处罚期间本人能访问什么、数据保留到何时、误封恢复后恢复哪些 | 误封后数据不可恢复，属不可逆处置 |
| 被封账号在他人处显示「因违规被封禁」 | 用中性文案，永久封禁与注销一致 | 暴露本人敏感处置状态 |
| 群被停用后会话直接从成员列表消失 | 写成员会话去向、历史可否查看、群主的通知与申诉 | 成员的历史数据被连带清除 |
| 处罚详情写出举报人或附他人举报原文 | 只写原因类别与依据，不披露举报人 | 举报人可能遭到报复 |
| 申诉结果只改状态不通知 | 系统会话通知并推送，详情页同步 | 用户不会反复打开详情页查结果 |

## 校准样例
最易写泛的功能：账号功能受限的详情页与申请复核。点击「提交」后只有「是否有网络」「服务端是否允许申诉」两个前置校验，不起判断链。告知载体、解除时间展示、申诉形态（一键申请复核，说明选填）、申诉次数与结果通知按推荐写成正文，卡内数值为示意，实际取值由业务定；受限原因的披露程度属必问，卡内留占位；申诉处理时长取决于审核运营能力，写 {待查}。

说明：
1. 入口：功能受限生效后，会话列表顶部常驻横幅「你的账号部分功能已受限，点击查看详情」，点击进入受限详情页；受限解除后横幅消失
2. 详情页逐行显示：处置类型「功能受限」；受限功能「添加好友」/「向非好友发起会话」/「创建群聊」/「邀请他人入群」；仍可使用「与已有好友和已加入的群聊天」；解除时间「{日期} {时刻} 自动解除」，按账号所在时区显示
3. 受限原因：{待定：原因与依据的披露程度，推荐：写明原因类别、依据的规则条款、是否由系统自动判定与可用的救济途径，不附具体内容，不披露举报人}
4. 受限期间点击受限功能：弹窗提示：「该功能暂时受限，将于 {日期} {时刻} 自动解除」，按钮「查看详情」/「知道了」
5. 详情页底部「申请复核」，点击后进入申诉页，可选填申诉说明（最多 500 字），「提交」按钮始终可点
6. 点击「提交」时无网络：toast 提示：「网络不可用，请检查网络后重试」，已填写内容保留
7. 服务端返回已有审核中的申诉（含其他设备提交的）：toast 提示：「申诉审核中，请勿重复提交」，返回详情页
8. 服务端返回已超过申诉期限：弹窗提示：「已超过申诉期限，无法提交申诉」，按钮「知道了」
9. 服务端返回受限已解除：toast 提示：「限制已解除，无需申诉」，返回详情页并刷新
10. 提交成功：详情页状态显示「审核中」，toast 提示：「申诉已提交，预计 {待查：申诉处理时长承诺} 内处理」
11. 审核结果在平台系统会话发送一条并推送；通过：「申诉已通过，账号功能已恢复」，限制立即解除，横幅消失；驳回：「申诉未通过，限制维持至 {日期} {时刻}」，消息底部附「了解其他救济途径」，点击进入帮助中心说明页；详情页提供一次「补充材料再次申诉」，再次驳回后不再提供申诉入口，「了解其他救济途径」保留
12. 到期自动解除：平台系统会话发送「你的账号功能限制已解除」，不需要任何操作
注：第 3 条受限原因的披露程度为占位项，写入前定稿

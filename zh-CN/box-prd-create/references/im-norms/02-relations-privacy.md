## 基线（默认遵循，置信度高）
- **[REL-01] 账号标识搜索添加**：可通过账号标识（手机号、用户名或账号 ID 等）搜索并添加对方。必定义：支持哪些标识；每种标识能否被搜到及对应的隐私开关；搜索无结果与因对方隐私受限时是否区分及各自文案。｜置信度：高
- **[REL-07] 拉黑后消息与通话不触达**：被拉黑方不能把消息送达、不能发起通话。必定义：被拉黑方发送后看到什么见 REL-22；拉黑后已有会话与聊天记录的去留、拉黑生效前已在途的消息、拉黑期间对方已发消息解除后是否补发（这三项属数据删除范围，按必问处理）。｜置信度：高
- **[REL-08] 拉黑联动切断资料类可见内容**：拉黑后被拉黑方看不到你的资料类可见内容（如在线状态、头像、动态）。必定义：逐项列出被切断的可见项（头像、在线、签名、动态等对被拉黑方的呈现属对方能感知到什么，整体按必问处理，合成一道题问）；题干或推荐理由写「与对方离线或关闭在线状态无法区分」时，须同时点明例外：切断头像本身可被察觉（被拉黑方在共同群里仍看到你的真实头像），由 Box 在知情下取舍；你的「最后上线」对被拉黑方是不可见还是退化为最模糊档（本条为该问题的唯一定义处，04 模块在线状态条目只引用本条；属对方能感知到什么，按必问处理）。｜置信度：高
- **[REL-09] 黑名单可解除**：设置中有集中的黑名单管理入口（列表、空态、逐个解除），拉黑功能必须同期提供，不放「建议后续」；可随时解除拉黑，解除后恢复双向触达。解除同样走二次确认（解除即恢复对方触达，不能一点即生效）。必定义：解除时的确认文案、解除后历史是否保留、拉黑与解除是否在本人所有已登录设备同步。｜置信度：高
- **[REL-11] 群邀请受被邀请人隐私限制**：被邀请人可通过「谁能邀请我入群」类设置限制被直接拉入群。必定义：邀请方看到的失败原因文案、替代路径（如发送邀请链接或先加好友）、批量邀请时部分失败的汇总文案。被邀请人隐私限制直拉只在本条定义，群模块的邀请条目不得给出绕过本条的选项。｜置信度：高
- **[REL-12] 对陌生人必须有接触闸门**：对陌生人的接触必须有控制手段，形态见 REL-21，接收方侧拦截见 REL-31；被闸门拦截的发送方看到明确原因，而不是无响应。｜置信度：高
- **[REL-14] 隐私项独立设置并多端同步**：每个可见性设置项独立，修改后立即在所有已登录设备生效。必定义：每项的默认档位、修改后对已有数据（历史动态、已发资料）的追溯规则。｜置信度：高

## 惯例（可默认，标建议）

- **[REL-02] 用户名唯一性与字符集**：用户名全局唯一、大小写不敏感，可删除并释放；字符集限定为有限集合（有产品仅允许小写字母、数字、下划线，也有产品允许连字符），具体由 ZYMIX 定。必定义：允许的字符集、首字符限制（可否数字开头）、长度上下限、「已被占用」「含非法字符」「过短」「过长」四类行内提示、更换频次。｜量级：下限 3 至 5 个字符，上限数十个字符｜置信度：中（仅两家）
- **[REL-03] 联系人备注仅自己可见**：联系人备注只在本人视图生效，对方不可见。必定义：备注长度上限、是否支持标签、备注与通讯录名、对方资料名的显示优先级、是否同步到其他设备。｜量级：备注上限百字符量级｜置信度：中（仅自己可见仅两家直接证据；显示优先级与标签各只有一家证据，已移入必定义）
- **[REL-04] 通讯录好友加入提示可关**：通讯录联系人注册后可给出提示，且有独立开关。必定义：默认开关状态、每人提示次数。｜置信度：中（仅两家）
- **[REL-05] 对方未接受前限制高打扰动作**：对方未接受或未回复前，发送方的高打扰动作（如连续发送、主动呼叫）受限，被限制时给出原因提示。必定义：未获回复前可发条数、是否可呼叫、每日可主动联系的陌生人数、超限文案；接收方侧的拦截开关另见 REL-31。｜量级：未获回复前可发 1 条至个位数条；每日主动联系人数上限的数值未取到，由 PRD 自定｜置信度：中（三家各限一类动作，形态不同，其中一家适用场景未确认）
- **[REL-06] 若采用好友验证申请，须有独立入口与状态**：申请须有独立列表或入口，不混入普通会话，列表内可见每条申请的处理状态。必定义：状态集合（如待处理、已通过、已拒绝、已过期、被过滤）、申请有效期、过期后重新申请规则、被过滤申请的入口。｜量级：证据未取到有效期天数，由 PRD 自定｜置信度：中（条件规则，仅两家；过期与被过滤各只有一家证据，已移入必定义）
- **[REL-10] 删除好友后对方再来信回到陌生人路径**：仅适用于采用请求或验证模型的产品；删除后对方再发消息按陌生人规则处理（需重新验证或变为消息请求），不再享有好友通道；通讯录模型下无此路径。必定义：删除前后会话与历史的去留（见 REL-23）。｜置信度：中（条件规则，仅两家）
- **[REL-24] 隐私档位含对个人的例外**：可见性设置项在档位之外支持对特定联系人的例外。必定义：每项支持的档位（如所有人/联系人/无人）、例外名单上限、是否在设置列表以数量摘要展示例外、例外对象被删除或拉黑后的处理；例外名单形态见 REL-30。｜置信度：中（例外三家一致但形态不同，其中一家为好友级权限；三档档位两家、数量摘要一家，均只在必定义）
- **[REL-26] 动态类内容可见范围独立于拉黑**：仅适用于有动态或故事类内容的产品；其可见范围须可独立于拉黑单独设置（排除名单、指定对象或「不让他看／不看他」）。必定义：默认可见范围（见 FEED-20）、排除与指定对象上限、是否提供「不看他」方向、历史动态的追溯规则。｜置信度：中（条件规则，三家一致但各家形态不同）
- **[REL-13] 互不可见对等**：（对等规则属隐私类，按必问处理：交付稿列入「待 Box 裁决」，推荐对等）自己关闭「最后上线」后，同样看不到对方的最后上线，设置项说明里写明此对等关系；已读回执开关的对等规则见 SEND-16。必定义：输入状态等其他可见项是否同样对等；对等的例外（如主动发消息会让对方看到在线、与对方从未聊过且未存联系人时的可见性）；是否允许付费档单向查看。｜置信度：中（最后上线对等仅两家直接证据，其中一家付费档可单向查看；输入状态对等只有一家证据，已移入必定义）

## 分歧点（必问的问 Box，可默认的按推荐写并列清单）
- **[REL-21] 陌生人接触模型**：选项 A：任何人可直接发消息，仅靠隐私设置限制／选项 B：陌生人首条先进「消息请求」，接受后才成会话，接受前不发已读／选项 C：好友验证申请，通过后才可聊天。推荐：B，理由：隐私优先且无需额外好友概念；若 ZYMIX 已有好友体系，以既有规则为准选 C。取舍背景：A 两家、B 一家、C 两家采用。｜级别：必问
- **[REL-22] 被拉黑方发送后的反馈**：选项 A：表现同正常发出，但永不送达、永不显示已读（静默）／选项 B：泛化失败提示，不含「拉黑」字样／选项 C：明示被拒收（如「消息已发出，但被对方拒收」）。推荐：A，理由：与国内主流产品明示拒收的做法相反（海外产品未取到官方说明，题干不得写「主流多为明示」或「主流多为静默」），属隐私取舍——不向被拉黑方暴露拉黑决定，且与通话侧被限制时不披露原因（见 MISC-26）一致。取舍背景：C 有两家国内主流产品直接证据；A 只有一家帮助说明的旁证（被拉黑列为看不到已读的原因之一），中置信；B 未见产品采用。面向国内用户、要求可感知时选 C。｜级别：必问
- **[REL-23] 删除好友时的聊天记录**：选项 A：同时清除聊天记录／选项 B：保留会话，仅解除关系／选项 C：弹窗让用户勾选「同时删除聊天记录」。删除前存在未处理款项（待收款、未领红包）时的拦截见 PAY-26。推荐：C，理由：数据完整优先，误删可避免。｜级别：必问
- **[REL-25] 首期隐私设置项范围**：选项 A：仅「谁能联系我」「谁能邀请我入群」「谁能搜到我」／选项 B：A 加在线状态、头像、资料简介／选项 C：B 加通话、转发署名、语音消息、生日。「允许通过名片添加我」开关见 RICH-44。推荐：B，理由：覆盖核心可见性且范围可控。｜级别：可默认
- **[REL-27] 用户名形态**：选项 A：可选公开用户名，无后缀／选项 B：用户名加系统分配数字后缀，搜索须输完整／选项 C：仅系统账号 ID，无自定义用户名。推荐：A，理由：改动最小，可被搜索由 REL-01 开关兜底。｜级别：可默认
- **[REL-28] 拉黑群的语义**：选项 A：拉黑群＝退群并拒收后续消息，成员不能再拉入／选项 B：仅静音，不退群／选项 C：不提供拉黑群，只能退群并拉黑邀请人或管理员。推荐：A，理由：防骚扰闭环完整。｜级别：必问
- **[REL-29] 已读回执与输入状态开关**：见 SEND-22（开关形态）；开关对等规则见 SEND-16；是否提供单聊已读回执见 SEND-09。
- **[REL-30] 隐私例外名单形态**：选项 A：仅「排除」名单／选项 B：「始终允许」与「始终禁止」双名单／选项 C：好友级单向屏蔽（不让他看、不看他）。三家各用一种。推荐：B，理由：隐私优先，既能收紧也能放开，且可展示「联系人（-3，+2）」式摘要。｜级别：可默认
- **[REL-31] 陌生人高频联系的拦截侧**：选项 A：仅发送方侧限制（未获回复前限条数、每日主动联系上限）／选项 B：加接收方可选开关，拦截未知账号的高频消息并可静音未知来电／选项 C：不做频控，靠拉黑与举报。推荐：B，理由：接收方自主可控且联系人不受影响（隐私优先）；发送方侧限制数值由业务定（量级见 REL-05）。｜级别：可默认

## 必问状态（本模块专属，补充通用状态矩阵）
- 对方状态：已拉黑我、已注销、已删除我；我与对方同群时，群内发言与@的可见性。
- 拉黑（以下为拉黑功能的必备配套，随本期写，不放建议后续）：黑名单集中管理入口（见 REL-09）；入群邀请双向拦截（见 REL-11、GRP-17）；群内他人引用或回复被拉黑方消息时拉黑方侧的呈现；拉黑生效时对方已在发送中的消息；拉黑期间对方发的消息解除后是否补发；与对方共同所在群里的显示。
- 多端：另一台设备已拉黑或已解除；另一台设备已通过或拒绝同一个申请。
- 特殊对象：对方是官方或系统账号（能否拉黑见 BOT-28）；双方互相拉黑；拉黑生效时刻的判定口径（以服务端接收时间为界）。
- 申请链路：申请过期、对方已注销、重复申请、申请时对方恰好改了隐私设置。
- 陌生人消息：离线时收到的陌生人首条、请求被删除后同一人再来、请求接受后的反悔入口（拉黑或举报）。
- 隐私设置：设置修改中途账号被登出；设置项依赖的对象（联系人）被删除；隐藏状态但主动发消息导致的在线曝光；关闭回执后群聊回执等例外项；设置只能在主设备修改时辅助端的显示。
- 拦截开关：开启期间被拦截的未知账号发送方看到什么；速率恢复后被拦截消息是否补发；陌生人来电被静音后的未接提示。
- 邀请入群：被邀请人隐私拒绝、被邀请人已拉黑邀请人、邀请链接已过期。
- 删除好友：24 小时内有共享类未完成事项时的风险提示；未处理的转账与红包的拦截见 PAY-26。

## 反模式
| 泛写/错写 | 正写 | 原因 |
|---|---|---|
| 「拉黑后对方无法发消息」 | 写被拉黑方看到什么提示、消息是否留在发送方、解除后是否补发 | 只写效果不写发送方反馈会导致研发自定 |
| 「陌生人可发消息需验证」 | 先判定模型（直聊／请求／申请），再写未接受前限制 | 三种模型状态机完全不同 |
| 「隐私设置：所有人／好友／无人」 | 逐项列设置项并写每项档位、例外名单、对等关系 | 各项档位不一致 |
| 「删除好友后清除记录」 | 写是否勾选、对方是否通知、对方再来信的路径 | 删除语义有三处分歧 |
| 「用户名唯一」 | 写字符集、首字符、长度、四类提示、更换频次 | 缺任一项即无法验收 |
| 「被限制时提示失败」 | 写限制原因、是否有替代路径、重试时机 | 无原因提示用户会反复重试 |

## 校准样例
最易写泛的功能：拉黑。点击后只有「是否有网络」一个前置校验，不起判断链。被拉黑方发送、呼叫时看到什么，以及最后上线对其如何显示，属对方能感知到什么，必问，卡内留占位；记录去留、多端同步、解除后是否补发按推荐写成正文。

说明：
1. 对方资料页内「拉黑」按钮常亮；点击后弹窗提示：「拉黑后，你将不再收到对方的消息和呼叫。」，按钮为「取消」「拉黑」
2. 点击弹窗内「拉黑」，无网络时：toast 提示：「网络不可用，请检查网络后重试」，保持未拉黑
3. 有网络时：拉黑生效，toast 提示：「已拉黑」，资料页按钮变为「解除拉黑」；拉黑状态同步到你已登录的所有设备
4. 拉黑生效后：
   a. 对方发送消息：消息不送达，对方看到 {待定：被拉黑方发送后的反馈，推荐：与正常发出一致但永不送达}
   a. 对方发起呼叫：不接通，对方看到 {待定：被拉黑方呼叫时的反馈，推荐：显示无人接听}
   a. 对方查看你的资料：看不到你的头像与在线状态，你的最后上线显示为 {待定：被拉黑方看到的最后上线，推荐：不可见}
   a. 你在会话输入栏发送消息：弹窗提示：「你已拉黑对方，解除后才能发送消息」，按钮为「取消」「解除拉黑」
5. 你与对方的会话及聊天记录保留在你的列表中，不因拉黑删除
6. 拉黑期间对方发出的消息不送达；解除拉黑后 {待定：拉黑期间的消息是否补发，推荐：不补发}

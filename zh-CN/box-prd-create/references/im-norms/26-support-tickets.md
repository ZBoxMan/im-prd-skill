# 客服与工单：通用反馈与申诉状态机（入口、状态、补充材料、时限、结果与满意度、人工与机器人客服）

> 适用：PRD 涉及帮助与联系客服入口、提交反馈、「我的反馈」列表与工单详情、工单状态与流转、需补充材料、已解决后的确认与重开、处理时限承诺、结果通知、满意度评价、机器人客服转人工、处理人身份展示时读本文件。本模块定义一套通用工单状态机，供举报（SAFE-12）、处罚申诉（ENF-10 至 ENF-13）、钱包交易争议（WAL-07）复用；各类型的入口、资格、次数与结果披露仍归原模块。举报形态见 SAFE-09；处罚与申诉见 22 模块；钱包争议入口见 WAL-07；平台系统会话见 BOT-09；机器人与 AI 的身份标识见 BOT-03、AI-03；频控提示见 SAFE-13。隐私请求与处罚复核的法定答复期限一律写「按上架地区合规要求」，本文件不给数值。证据见 evidence/26-support-tickets.md。

## 基线（默认遵循，置信度高）
- **[SUP-01] 应用内提供帮助与联系客服入口**：应用内有固定的帮助与联系客服（意见反馈）入口。必定义：入口位置与文案（可参考：放在设置内，两家直接证据）；是否先展示常见问题再给联系入口（可参考：一家直接证据在联系前先提示查看常见问题）；问题类型清单与按类型分流（隐私请求、无障碍、钱包、账号安全是否走独立入口）；无法登录时从哪里发起（可参考：网页表单，两家直接证据）以及登录后如何在账号内看到该工单；工单体系范围见 SUP-09。｜量级：不适用｜置信度：高
- **[SUP-02] 诊断日志与技术信息经用户确认后才附带**：提交反馈或出错时附带诊断日志、设备与技术信息，须先让用户知情并确认（弹窗询问、勾选项或提交前声明），不静默上传。必定义：附带内容清单及是否包含聊天内容的说明（可参考：一家直接证据写明不会泄露对话内容）；默认是否勾选附带（属隐私默认值，按必问处理）；日志的保留期限；加密会话的内容是否可能进入日志及如何排除。｜量级：不适用｜置信度：高

## 惯例（可默认，标建议）
- **[SUP-04] 状态变化与结果主动通知**：工单进入需补充、已解决、已关闭时主动通知用户，点击进入工单详情；工单详情状态同步更新。必定义：通知载体（可参考：平台系统会话发一条可回看的通知并推送；载体只有一家直接证据，另一家为推送，移入必定义）；哪些状态变化发通知（受理是否也通知）；通知文案；推送被关闭或系统会话被删除后的补偿（下次打开「我的反馈」显示未读标记）；系统会话形态见 BOT-09；处罚申诉的通知载体见 ENF-13；举报的反馈文案见 SAFE-12。｜量级：不适用｜置信度：中（状态变化主动通知两家直接证据）
- **[SUP-05] 工单从争议对象处发起并自动带上对象**：对具体对象有疑问时，从对象所在处（交易详情、处罚提示、消息或资料页、通话结束页）发起，自动带上对象标识，用户不必手填单号。必定义：每类对象的发起入口；带上的字段与对用户是否可见；对象已删除、已撤回或已过期时能否发起。钱包交易见 WAL-07，处罚申诉见 ENF-02，举报对象见 SAFE-11。｜量级：不适用｜置信度：中（两家直接证据）
- **[SUP-06] 客服不会索要验证码与密码的提示**：见 SAFE-15（客服入口、客服会话顶部与提交页的防冒充提示同样按本条）。
- **[SUP-07] 机器人客服的身份标识**：见 BOT-03（与真人账号可区分的类型标识；AI 生成的回复标识见 AI-03，自动回复标识与「转人工」入口本身见 BOT-29）。本模块只管转人工的触发与接续（SUP-15）与处理人身份展示（SUP-16）。
- **[SUP-08] 举报与处罚申诉的类型规则**：见 SAFE-09（举报形态；反馈文案见 SAFE-12）；处罚申诉的可申诉范围、形态、次数、时长承诺与通知载体见 ENF-09 至 ENF-13。两者复用 SUP-10 的状态机。

## 分歧点（必问的问 Box，可默认的按推荐写并列清单）
- **[SUP-03] 同一对象已有未关闭工单时能否再提交**：选项 A：针对同一对象（同一笔交易、同一次处罚、同一被举报对象）已有未关闭的工单时不新建，提示并引导到原工单补充或查看进度，后续追加计入原工单／选项 B：允许再次提交，处理方侧合并。推荐：A，理由：避免重复工单与重复处理，用户在一处看进度；已知一家直接证据（同一笔交易不重复受理），另一家只写绕过流程不会加快处理，不是同一件事。必定义：对象的判定口径（交易单号、处罚记录、被举报账号或消息）；一般反馈不绑定对象时是否也限制重复提交，及其频控提示（写法见 SAFE-13）；多端同时提交时以服务端先受理的一张为准。｜级别：可默认
- **[SUP-09] 工单体系的范围**：选项 A：统一工单体系，一般反馈、举报、处罚申诉、钱包交易争议共用 SUP-10 的状态机与同一个「我的反馈」列表，入口仍在各自对象处，时限、通知与次数按类型分别配置／选项 B：只有一般反馈与钱包争议走工单，举报与处罚申诉各自独立、不进列表／选项 C：不设工单，一般反馈以客服会话答复，举报、申诉、争议各自独立。推荐：A，理由：用户在一处就能看到所有待处理事项的状态，补充与重开的规则只定义一次；与现有产品做法相反（已知产品都按争议对象分流，各流程的状态、时限与通知互相独立，没有统一列表），属用户理解优先取舍。｜级别：必问｜定型：是
- **[SUP-10] 通用工单状态机**：选项 A：五个状态加重开，已提交（服务端已受理，尚未开始处理）、处理中（已分派处理人或进入审核）、需补充（等待用户补充材料，见 SUP-11）、已解决（处理方已给出结果，等待用户确认或期满，见 SUP-12）、已关闭（终态，不再接收补充）；已解决可在期限内重开回到处理中／选项 B：三个状态，已提交、处理中、已答复，答复即结束，有新问题另提交／选项 C：不展示状态，只在结果出来时通知。推荐：A，理由：用户能理解当前在等谁，补充与重开都有明确去向；已知唯一完整的终端样本是三态加「继续投诉」回到起点，A 在其上拆出需补充与终态。各类型可沿用本类叫法，但须映射到这五个状态：处罚申诉的审核中为处理中，已通过与已驳回为已解决的两种结果，已过期为已关闭；钱包争议的已答复为已解决；举报只用已提交、处理中、已关闭三态，结果是否告知举报人按 SAFE-12。用户撤销：已提交与处理中可撤销，撤销即已关闭。时限口径见 SUP-13，通知见 SUP-04。｜级别：可默认
- **[SUP-11] 需补充材料**：选项 A：处理方发起需补充并写明要补什么，经平台系统会话通知；用户在工单详情补充文字与图片，提交后回到处理中；等待设期限，逾期自动转已关闭并通知可重新提交；需补充期间暂停处理时限计时／选项 B：不设该状态，用户随时可追加留言，处理方随时回复，状态不变／选项 C：不支持补充，材料不足即给出结果，请重新提交。推荐：A，理由：用户知道处理在等自己、要补什么；已知一家用「有待回复的用户留言」标记，做法接近 B。补充材料的类型与数量上限（截图、文件；日志按 SUP-02）、等待期限由业务定。｜级别：可默认
- **[SUP-12] 已解决后的收口与重开**：选项 A：已解决时用户可点「已解决」直接关闭，或在期限内点「仍未解决」并填写原因重开一次，回到处理中；期满无操作自动转已关闭；重开次数用尽或已关闭后只能新建工单，新工单自动关联原工单／选项 B：给出结果即关闭，不可重开，有异议须新建／选项 C：不限重开次数，记录重开次数供处理方参考。推荐：A，理由：误判或答非所问仍有一次补救，又不被反复刷；已知唯一完整样本为不限次数地「继续投诉」回到待处理、无反馈默认已解决，接近 C 加自动收口。处罚申诉的再申诉次数见 ENF-11。｜级别：可默认
- **[SUP-13] 处理时限承诺写进卡的口径**：选项 A：按工单类型分别承诺，写成「通常在 {N} 个工作日内答复」，写明起算点（服务端受理时间）、工作日按账号所在时区（见 UX-36）与哪个日历、需补充期间暂停计时；超过承诺仍未答复时状态旁显示仍在处理，工单不自动关闭／选项 B：不承诺时长，只说「处理后会通知你」／选项 C：承诺固定时长，超时自动升级处理或给补偿。推荐：A，举报按 SAFE-12 不承诺，处罚申诉是否承诺见 ENF-12，理由：用户能理解当前状态，减少重复提交与催办；已知有承诺的都集中在对象明确的争议、处罚复核与隐私请求，一般咨询多不承诺或只给区间（量级：一至数个工作日，争议与复核从一天到半个月不等）。时长取值取决于客服与审核运营能力，属事实源缺口，写 {待查} 进未决项；隐私请求的法定答复期限按上架地区合规要求。｜级别：可默认
- **[SUP-14] 满意度评价**：选项 A：工单转为已解决时邀请一次评价，与 SUP-12 的「已解决」/「仍未解决」合并为一步，另可选星级与说明，可跳过，不影响状态流转；举报与处罚申诉不邀请评价／选项 B：只在帮助文章底部问是否解决了问题，工单不评价／选项 C：不做评价。推荐：A，理由：评价与确认合并不另打扰，服务质量可度量；与现有产品做法相反（已知产品只在帮助文章一层问是否解决，工单级评价没有样本），属服务质量可度量取舍；举报与申诉的结果不由满意度决定，邀请评价易被理解为能影响结果。｜级别：可默认
- **[SUP-15] 机器人客服转人工的触发与接续**：选项 A：转人工入口的形态见 BOT-29；连续两次未识别、或问题属账号被盗、资金、处罚类时主动给出转人工；转接时带上已有对话与问题类型，用户不必重述；人工不在服务时间或排队超时时转为留言工单，进入 SUP-10 状态机，答复经平台系统会话通知／选项 B：须与机器人多轮对话后才出现转人工／选项 C：没有实时人工，只能提交工单。推荐：A，理由：用户能随时找到人，敏感问题不被机器人挡住；一家平台政策要求自动化回复须提供直达人工的路径。排队位置与预计等待时间是否展示、人工服务时间由运营定。｜级别：可默认
- **[SUP-16] 是否向用户披露处理人身份**：选项 A：只显示类别「人工客服」/「智能客服」，不显示任何个人信息／选项 B：类别加客服工号或化名，不显示真实姓名与照片／选项 C：类别加真实姓名。推荐：B，理由：用户能在评价、重开与投诉时指认具体处理人，又不暴露员工个人信息；三个选项都满足人工与机器的区分（见 AI-03）；无产品直接取证，属推断。级别理由：处理人是员工，工号或化名是员工信息，不是用户的隐私默认值，不改变主流程，也不涉及资金与不可逆处置，故可默认。另：工单结果是否由系统自动作出、是否告知用户：处罚申诉见 ENF-08；其余工单按 ENF-08 推荐 B 的口径，结果通知里写明是否由系统自动判定。｜级别：可默认

## 必问状态（本模块专属，补充通用状态矩阵）
- 多端：一台设备提交或补充，其他设备的列表与详情何时刷新；两台设备同时补充材料或同时点「仍未解决」以哪次为准。
- 离线与弱网：提交或补充时断网，已填内容与已选图片是否保留；附件上传失败、部分成功、超出数量或大小上限；状态变化时离线，上线后先看到什么。
- 对象变化：工单处理中对象被删除、被撤回、交易已退款、处罚已到期自动解除、被举报账号已注销；处理方给出结果时对象已不存在。
- 账号变化：工单进行中注销账号（钱包未结争议拦截注销见 WAL-18）；账号被封禁时能否查看与补充原有工单（封禁时的申诉入口见 ENF-02）；无法登录时网页提交的工单登录后如何归到账号下；换绑手机号后历史工单。
- 期限边界：需补充等待期、重开期、自动关闭的截止时刻以服务端时间为准；截止瞬间用户正在提交补充；承诺时长内遇节假日。
- 转人工：排队中退出会话或切到后台；转接中断网；人工结束会话后用户继续发消息；非服务时间转留言后用户又在机器人会话追问。
- 工单记录：已关闭工单在列表保留多久；用户能否删除工单记录、删除后处理方侧是否保留（按必问处理）；工单里的证件与截图的保留期。
- 地区差异：隐私请求、处罚复核的法定答复期限与是否须人工参与，按上架地区合规要求。

## 反模式
| 泛写/错写 | 正写 | 原因 |
|---|---|---|
| 只画一个「提交反馈」按钮，提交后无下文 | 写受理后的状态、在哪查进度、结果怎么通知、需补充与重开的去向 | 工单是有状态的流程，缺分支就无法实现 |
| 状态只列名称 | 每个状态先各用一行说清含义，再写进入与离开条件 | 已解决与已关闭、处理中与需补充最易被混用 |
| 承诺「24 小时内处理」但不写起算点与超时表现 | 写起算点、工作日口径、需补充期间是否暂停、超时后的状态显示 | 承诺无法验收，超时后用户只看到失约 |
| 需补充时只发一条消息，工单状态不变 | 状态转为需补充，写明要补什么、期限多长、逾期去向 | 用户不知道处理在等自己，工单长期悬挂 |
| 已解决后不能表达不同意 | 给「仍未解决」与重开次数，用尽后给新建入口并关联原工单 | 用户只能重复新建，处理方看不到前情 |
| 机器人会话里找不到人工 | 转人工入口按 BOT-29 提供，敏感类型主动转，转接带上已有对话 | 机器人挡住账号被盗、资金类急事 |
| 机器人回复与人工回复外观相同 | 按 BOT-03、AI-03 标识，处理人身份展示按 SUP-16 定 | 用户无法判断答复是否经人工确认 |
| 日志默认静默上传 | 附带前让用户确认，说明内容清单、是否含聊天内容 | 日志可能含个人信息，静默上传违背知情 |
| 举报与申诉结束后邀请打分 | 举报与申诉不邀请满意度评价 | 用户会以为评分能改变处理结果 |

## 校准样例
最易写泛的功能：「我的反馈」工单详情页与状态流转。用户在详情页的操作都只依赖「是否有网络」与服务端返回的当前状态，不起判断链。工单体系范围已在定型时确定为统一工单体系；状态集、需补充、已解决后的收口与重开、满意度、撤销、时限口径与处理人显示按推荐写成正文，卡内数值为示意，实际取值由业务定；本例没有必问项；各问题类型的处理时长取决于客服运营能力，写 {待查}。

说明：
1. 入口：「设置」页的「帮助与反馈」中点击「我的反馈」，列表按最近更新时间倒序，每行显示问题类型、提交时间与当前状态；举报、处罚申诉与钱包争议也在此列表，各自从原对象处发起
2. 状态：
   已提交：服务端已受理，尚未开始处理
   处理中：已有客服或审核人员在处理
   需补充：处理方要求补充材料，等待你回复
   已解决：处理方已给出结果，等待你确认
   已关闭：工单结束，不能再补充或重开
3. 提交成功：进入工单详情，状态为「已提交」，toast 提示：「反馈已提交，通常在 {待查：各问题类型的处理时长承诺} 内答复」
4. 时限口径：处理时长从服务端受理时间起算，按工作日计，处于「需补充」期间暂停计时；超过承诺时长仍未答复的，状态旁显示「处理时间较长，仍在处理中」，工单不自动关闭
5. 需补充：平台系统会话发送「你的反馈需要补充材料」并推送，点击进入工单详情；详情顶部显示处理方需要补充的内容，底部「补充材料」可填写说明（最多 500 字）并添加截图（最多 3 张）；提交后状态回到「处理中」；7 天内未补充自动转为「已关闭」，系统会话发送「因未补充材料，反馈已关闭，可重新提交」
6. 已解决：平台系统会话发送处理结果并推送；一般反馈与钱包争议的详情页显示结果与「已解决」/「仍未解决」两个按钮，下方可选 1 至 5 星评价与说明，不评价不影响状态；举报不经过「已解决」，处理结束直接转为「已关闭」；处罚申诉的结果与再申诉在申诉详情页处理；举报与处罚申诉都不显示这两个按钮与评价
7. 点击「已解决」或 7 天内无操作：状态转为「已关闭」
8. 点击「仍未解决」：填写原因（必填，最多 500 字）后提交，状态回到「处理中」；每张工单可重开 1 次，重开后再次解决时只显示「已解决」，并在底部显示「提交新的反馈」，新反馈自动关联本工单
9. 撤销：「已提交」与「处理中」状态下，详情页底部显示「撤销反馈」，点击后弹窗提示：「撤销后将停止处理，确定撤销？」，按钮「撤销」/「取消」；撤销后状态为「已关闭」
10. 处理人显示：人工处理的显示「人工客服」与客服工号，机器人处理的显示「智能客服」，不显示真实姓名与照片
11. 提交补充材料、重开原因或撤销时无网络：toast 提示：「网络不可用，请检查网络后重试」，已填写内容保留
12. 服务端返回状态已变化（如其他设备已补充或已关闭）：toast 提示：「反馈状态已更新」，刷新详情页
注：第 3 条处理时长待客服运营答复

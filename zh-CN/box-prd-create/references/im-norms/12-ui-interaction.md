# 通用交互（手势、菜单、反馈、状态、角标、无障碍、国际化、触感与动效）

> 适用：画原型屏与写说明卡时凡涉及手势、长按菜单、多选、提示与弹窗、断网与加载失败、角标、无障碍与多语言处必读。说明卡里无障碍与动效只写定性要求（如「点击热区需满足平台无障碍标准」「动效遵循系统减弱动态设置」），不写像素、时长、曲线。证据见 evidence/12-ui-interaction.md。
> 取证边界：本机客户端只取到静态字符串；官方帮助中心只覆盖功能规则、几乎不描述手势与动效。手势与动效的实际表现以开源客户端源码与平台、无障碍标准为准。五家中仅两家直接取证的条目归惯例，仅一家或全靠推断的归分歧点；主要依据平台或无障碍标准、五家直接证据不足的条目暂归惯例，括号写明。

## 基线（默认遵循，置信度高）

### 手势、长按与多选
- **[UX-07] 多选模式**：入口为长按菜单「选择」；进入后底部操作条按所选消息类型显示可用项（转发、删除等）。必定义：已选数量的显示位置、选中集合清空后是否自动退出、是否另提供合并转发（见 ACT-14）、混选己方与他人消息时删除的可用范围；选中与转发条数上限见 ACT-02，一次转给几个会话见 ACT-19。｜量级：—｜置信度：高

### 反馈、提示与确认
- **[UX-11] 何时弹确认**：不可恢复或影响他人的操作必须确认（为所有人撤回、清空聊天记录、退出群聊、拉黑）；删除会话用确认还是限时撤销见 LIST-26；「仅自己删除」消息后是否给限时撤销见 ACT-26。必定义：每个操作属「确认」还是「撤销」；可恢复的常见操作（归档、静音、置顶）是否免确认、是否给带「撤销」的提示条。｜置信度：高
- **[UX-13] 不可逆文案写明范围**：说明后果生效范围与可恢复性（仅本机 / 所有设备 / 对方也删除；「此操作无法撤销」）。必定义：每个不可逆操作的范围句（含与备份的关系：删除后能否从备份找回）；若同时提供删除聊天与「不显示聊天」这类相近操作，文案如何区分「是否清空记录」「新消息是否重新出现」。｜置信度：高

### 断网、加载、空、错误
- **[UX-20] 前置拦截说明具体原因**：不可操作时在执行前说明原因而不是静默失败（「内容已过期，无法收藏」「图片未下载，无法发送」「不能发送空白消息」「文字过长，无法发送」）。必定义：拦截条件与文案。｜置信度：高

### 国际化
- **[UX-33] 文案整句带变量**：文案用带变量的整句（「{N} 条未读消息」），不拼接片段。必定义：时间格式、12 或 24 小时制、星期与日期顺序、数字分隔是否随系统与语言区域；有复数变化的语种如何处理复数。｜置信度：高

## 惯例（可默认，标建议）

### 手势、长按与多选

- **[UX-01] 手势必有等价入口**：滑动回复、左右滑操作、拖拽排序、双击等依赖手势的操作，必须在长按菜单、编辑模式或按钮中有非手势的等价入口；手势只做快捷方式，不做唯一入口。必定义：每个手势对应的等价入口。｜置信度：中（仅两家直接证据，另有无障碍标准旁证）
- **[UX-02] 边缘返回优先**：屏幕左右边缘起滑留给系统返回手势；列表行与气泡的横滑从行内或气泡内部起滑，不与边缘返回冲突；一级页没有返回。｜置信度：中（一家直接证据加平台规范（系统边缘返回手势）；另一家为源码推断）
- **[UX-03] 滑动回复**：气泡朝屏幕中间方向横滑，越过触发阈值后松手即进入回复态；滑动过程中气泡跟手、回复图标渐显，松手后气泡回弹；越过阈值瞬间给一次触感且整个手势只触发一次；RTL 下滑动方向反转。必定义：哪些消息不可滑（系统消息、发送中消息、无发言权限的会话等逐项定）。｜量级：阈值为一小段横向位移，不要求滑满｜置信度：中（仅两家直接证据；不可滑范围只有旁证，已改进必定义）
- **[UX-04] 长按消息弹层**：长按弹出「快捷回应条 + 操作菜单」，被选中的气泡与背景分离，菜单靠近气泡并按剩余空间决定朝上或朝下；弹出瞬间一次触感；菜单只显示当前可用项，不可用的隐藏而不是置灰；项目少而精，分组不超过约 3 组，子菜单最多 1 层；同组项目要么都有图标要么都没有。必定义：快捷回应条的常用表情数量与「更多」入口。｜量级：菜单项约 5–10 项｜置信度：中（回应条加菜单仅两家直接证据；隐藏不置灰、分组与图标规则来自平台规范与一家源码）
- **[UX-05] 菜单项顺序**：回复排第一；删除类排最后并使用破坏性样式；举报仅对他人消息出现。必定义：完整菜单项顺序（按消息类型），含复制、转发、编辑的相对位置；菜单项中哪些在多选操作条也提供。｜置信度：中（回复第一、删除最后仅两家直接证据；中间顺序两家不一致，已改进必定义）
- **[UX-06] 菜单项按类型与状态差异**：长按菜单项按消息类型与发送状态增减，只显示当前可用项；一次性查看的消息不提供转发、复制、保存。必定义：各类型与状态的完整菜单项清单。可参考（以下各子句多为一家证据，只作参考、不作默认规则）：文本有回复、复制、转发、编辑（仅己方、未超时）、删除、选择；图片/视频多「保存」，有文字说明才有「复制」；语音无「复制」；文件多「保存 / 另存」；已撤回只保留「删除」（己方可含「重新编辑」）；系统消息无菜单；发送中不可转发、置顶、回应；发送失败首项「重新发送」；投票「结束投票」仅发起人；他人消息多「举报」，己方消息多「为所有人撤回」与「信息」（回执详情，随回执层级裁决）；限时消息可转发，转入未设限时的会话后不再消失。｜置信度：中（类型差异方向多家一致；一次性消息不可转发、复制、保存有两家直接证据；其余子句已移入必定义作参考）

### 反馈、提示与确认

- **[UX-08] 反馈组件选型**：toast（无动作的轻提示，如「已复制」「已保存」，自动消失）；snackbar（底部提示条，可带一个动作如「撤销」「重试」，可被划掉）；alert（模态弹窗，只用于需要用户决定或不可逆的问题）；行内提示（字段或列表项局部错误）；横幅（持续性系统状态：断网、同步中、权限被拒）；骨架屏（首屏加载）。iOS 无原生 toast，需自绘并保证可被读屏读出。必定义：每类提示的触发条件与是否带动作。｜置信度：中（带「撤销」的提示条有三家、toast 有两家直接证据，其余组件分工来自平台规范；alert 用途有一家单键告知弹窗反例）
- **[UX-09] 仅告知不用 alert**：只告知结果、不需要用户决定的信息用 toast、行内提示或横幅；启动时发现的问题（无网络）用常驻横幅，不在启动时弹窗；基于用户已发起意图的多选项（如「保存草稿 / 放弃修改 / 继续编辑」）用底部操作菜单而不是 alert。必须阻断的账号级后果才用单按钮告知弹窗。｜置信度：中（依据平台规范与一家短句提示，另一家单键「我知道了」告知弹窗为反例）
- **[UX-10] 提示条时长与读屏**：带动作的提示条停留更久且可由用户延长，纯提示较短；同一时刻只显示一条，后一条替换前一条；状态类提示需让读屏在不改变焦点的前提下读出。｜量级：纯提示数秒，带动作的更长，留足操作时间｜置信度：中（依据平台与无障碍规范，五家直接证据仅一家带「撤销」提示条的时长）
- **[UX-12] 确认弹窗文案与按钮**：标题一句话说明将发生什么（「删除该聊天？」），正文只在需要时补一句后果；按钮不超过 3 个；主操作用动词短语（「删除」「退出」「不显示」），不用笼统的「确定」；取消按钮文案固定为「取消」；破坏性主操作用破坏性样式；取消与主操作的相对位置遵循平台惯例，PRD 只写「主操作」「取消」两个角色，不自定义顺序。｜量级：按钮 2–3 个｜置信度：中（标题句式、动词按钮与「取消」有三家直接证据，一家部分弹窗仍用「确定 / 取消」为反例；按钮数上限来自平台规范）
- **[UX-14] 放弃未保存内容确认**：编辑或草稿有改动时关闭或返回，弹「放弃修改？」，按钮「放弃」「继续编辑」；无改动直接退出。｜置信度：中（仅两家直接证据）

### 断网、加载、空、错误

- **[UX-15] 断网状态**：无网络时用常驻状态提示（标题区状态文案或顶部横幅，形态见 UX-D4），不用弹窗，网络恢复后自动消失；此时输入栏仍可输入。未发出消息的排队、自动续发、寿命与转失败的呈现见 SEND-10。必定义：状态文案。｜置信度：中（「输入栏仍可输入」有三家直接证据；「常驻状态提示、不用弹窗」一家直接证据加平台规范（仅告知的信息不用弹窗，见 UX-09））
- **[UX-16] 无网络与服务连接失败分别提示**：「当前网络不可用」与「连接服务器失败」文案不同，后者给「重试」入口；限频类提示独立文案（「操作过于频繁，请稍后再试」），能给出等待时长的写明时长；服务端拒绝（被封禁、需先同意条款、超出用量）与网络问题的提示分开。｜置信度：中（限频独立文案有三家直接证据；无网络与连接失败分开仅两家；服务端拒绝分类只有旁证）
- **[UX-17] 加载态**：先显示骨架或占位行，不用整页遮罩；加载期间允许用户继续其他操作；可确定耗时用进度条，不可确定用转圈；分页加载用列表边缘的小指示。｜置信度：中（主要依据平台规范，五家直接证据仅一家列表加载文案）
- **[UX-18] 空状态**：首次无数据的空状态写明引导文案并给一个主操作，不留空白页。必定义：筛选无结果、搜索无结果、系统权限被拒是否各自独立及文案与主操作（可参考：搜索无结果写「没有找到与「{关键词}」相关的结果」并给换词提示，权限被拒的提示与去设置入口见 DISC-02）；空状态的结构（如居中「标题 + 一句说明 + 一个主操作」）。｜置信度：中（首次无数据的空态文案有三家直接证据；搜索无结果与权限被拒只有一家证据，居中结构只有旁证，均已移入必定义）
- **[UX-19] 错误与重试**：页面或列表加载失败 → 居中说明 + 「重试」；消息发送失败 → 气泡旁重发；操作失败 → toast 或 snackbar 并带「重试」；文案写原因与可做的事，不用「错误」「警告」等笼统词；失败提示都对应一个可重试入口或明确说明。｜置信度：中（失败提示配重试入口或说明有三家直接证据；「不用笼统词」有一家通用报错句反例）

### 角标

- **[UX-21] 数字与红点**：同一入口数字与红点不并存；数字与红点的分工见 UX-D7；角标的读屏标签读成「{N} 条未读」，不读单独数字。｜置信度：中（不并存只有一家相近做法加旁证，读屏读法依无障碍标准）
- **[UX-23] 静音会话的角标弱化**：静音会话的未读数用弱化样式，与未静音未读区分；@ 标识仍保持强调。是否计入总角标见 NOTI-26。｜置信度：中（弱化样式仅两家直接证据）
- **[UX-24] 应用图标角标**：只表示未读消息的数量，不承载与消息无关的数字；用户阅读后立即更新。｜置信度：中（角标只计未读有两家直接证据，「阅读后立即更新」来自平台规范）

### 无障碍（说明卡只写定性要求）

- **[UX-25] 点击热区**：所有可点元素的点击热区需满足平台无障碍标准，密集区域（行内图标、角标、菜单项）不得因视觉小而缩小热区；相邻目标间需有足够间距防误触。｜置信度：中（依据平台无障碍标准，五家无直接证据）
- **[UX-26] 动态字体**：支持系统字号放大，列表行高随字号增长，摘要行数上限不变，核心信息与按钮动词不被截断。｜置信度：中（依据平台无障碍标准，五家仅一家有摘要行数上限证据）
- **[UX-27] 读屏标签**：仅图标的按钮必须有文字标签（「发送」「语音」「更多」）；带状态的控件读出状态（「已静音」「已置顶」）；压缩显示的时间提供完整读法（「3 分钟前」）；消息读出顺序为发送者、内容、时间、状态；可见文字是无障碍名称的一部分，改版时同步更新。｜置信度：中（两家直接证据，另有无障碍标准）
- **[UX-28] 对比度与非颜色传达**：深色与浅色模式均需满足无障碍对比标准；状态不能只靠颜色表达（失败态用图标加文字，静音用图标；已送达与已读不得只靠勾的颜色区分）。｜置信度：中（依据平台无障碍标准；已送达与已读只靠勾的颜色区分有一家反例，按裁决梯度「无障碍与可恢复」保留）
- **[UX-29] 减弱动态与自动播放**：系统开启「减弱动态效果」时，动效简化为淡入淡出或直接切换；自动播放的动图超过数秒需提供暂停；不依赖摇晃或倾斜触发功能。｜量级：自动播放超过约 5 秒要可暂停｜置信度：中（依据无障碍标准，五家无直接证据）
- **[UX-30] 悬浮元素不遮挡**：键盘弹起时输入栏上移、列表保持当前阅读位置；跳底按钮、提示条、输入栏不得完全遮挡当前焦点元素。｜置信度：中（依据无障碍标准；跳底按钮一家直接证据，键盘弹起行为为推断）

### 国际化

- **[UX-31] RTL 镜像**：整体布局镜像；己方与对方气泡位置互换；返回箭头、滑动回复方向、进度条与滑块镜像；表示前进或后退的图标镜像；数字不反转，照片、插图、品牌标识不镜像；混排文本按首个强方向字符决定段落方向，时间贴近气泡内侧角落。｜置信度：中（依据平台 RTL 规范，五家仅一家有方向随语言的直接证据）

### 触感与动效（只写规则）

- **[UX-34] 触感**：每种触感对应唯一含义，只用于确认或阈值时刻：长按弹出菜单、滑动回复越过阈值（一次）、多选勾选、录音开始 / 锁定 / 取消、发送失败（可选）；普通点击不加；触感需与视觉或声音配合，不单独存在。｜置信度：中（依据平台触感规范与一家阈值振动源码；录音等时刻为推断）
- **[UX-35] 动效**：动效只服务于让用户看懂位置变化：发送的气泡从输入框位置上浮入列表；用户停在底部时新消息才有进入动画，翻看历史时静默入列；删除时行或气泡折叠收起并平滑补位；跳转历史消息后落点气泡短暂高亮；滑动回复气泡跟手并回弹；「正在输入」出现与消失不得让列表跳动。动效遵循系统减弱动态设置（UX-29）。｜置信度：中（一家源码加旁证；减弱动态的退化来自平台规范）

## 分歧点（必问的问 Box，可默认的按推荐写并列清单）
- **[UX-D1] 双击消息**：选项 A：快速回应／选项 B：编辑自己的消息／选项 C：回复该消息／选项 D：不做。推荐：D，理由：与现有产品做法相反（已知两家分别用双击回复、编辑，快速回应仅为记忆未取证），属无障碍与可恢复取舍：双击是无提示的隐性手势，且易与多选、图片放大冲突。｜级别：可默认
- **[UX-D2] 消息菜单形态**：选项 A：靠近气泡的浮层列表／选项 B：底部操作面板／选项 C：气泡上方横向图标条。推荐：A，理由：两家有直接证据采用 A，菜单项少而精时离触发点最近；C 只有行业观察，未取证。｜级别：可默认
- **[UX-D3] 滑动是否全滑直接执行**：选项 A：全滑即执行第一个动作／选项 B：只露按钮，必须点击才执行／选项 C：全滑只执行非破坏性动作，破坏性动作必须点击。推荐：C，理由：可恢复（删除类不因误滑被执行）；已知一家全滑即执行首个动作，另一家只对归档这类非破坏性动作全滑执行，推荐与前者不同，属可恢复取舍。｜级别：可默认
- **[UX-D4] 断网提示形态**：选项 A：标题区状态文案（「连接中…」）／选项 B：顶部常驻横幅／选项 C：先标题区文案，持续一段时间后升级为横幅。推荐：C，理由：用户理解（短暂抖动不打扰，持续断网有明确提示）；直接证据只见一家用 A，C 为组合方案，属用户理解取舍；升级时长由业务定。｜级别：可默认
- **[UX-D5] 未读数上限**：选项 A：99+／选项 B：999+／选项 C：不封顶／选项 D：紧凑缩写。推荐：A，理由：两家在一级入口或会话行采用 99+，位数短、不撑破布局；另有一家会话行不封顶、一家用缩写。｜级别：可默认
- **[UX-D6] 静音会话是否计入总角标**：见 NOTI-26（只在该处定义）。
- **[UX-D7] 红点与数字的用法**：选项 A：只用数字／选项 B：静音会话有未读时用点／选项 C：私聊与群聊用数字，动态或发现类入口用红点。推荐：C，理由：用户理解（数字表示待处理条数，红点表示有更新）；一家动态类入口用红点，B 只有旁证。｜级别：可默认
- **[UX-22] 三处未读数是否同一规则**：选项 A：会话行、一级入口与应用图标用同一封顶规则（应用图标由系统渲染时除外）／选项 B：一级入口与应用图标封顶，会话行显示完整数字。推荐：A，理由：用户理解（同一未读数在不同位置读法一致）；已知一家采用 B，一家各处统一用缩写。封顶形式与上限值见 UX-D5，口径（按消息数还是会话数）以 08 模块为准。｜级别：可默认
- **[UX-32] 长语种适配**：选项 A：按钮与标签文案在长语种下允许换行或增高，不得截断动词；会话名单行省略，摘要最多 2 行；不依赖固定宽度／选项 B：固定宽度，超长文案统一截断加省略号。推荐：A，理由：无障碍与可恢复——截断动词会让用户看不懂按钮；取舍背景：五家无产品直接证据，依通用国际化做法。选 A 时必定义：关键按钮的最长可接受字数预算。｜级别：可默认
- **[UX-36] 规则类时间的时区口径**：适用于日切、每日计数清零、到期日、解除时间、处理时限截止等由规则计算出的时间；消息、通话、动态的时间戳按本机时区显示，不在本条；用户自己选定的绝对时间（投票截止、定时发送、提醒时间）也不在本条，服务端存绝对时间，选择与显示都按本机当前时区。选项 A：一律按账号所在时区计算与显示（账号所在时区 = 服务端为账号记录的时区，取自账号地区设置，未设置时取注册地区，以 ZYMIX 既有账号字段为准），卡内统一写「按账号所在时区」／选项 B：按账号所在时区计算，按本机时区显示／选项 C：一律按本机时区。推荐：A，理由：改本机时间或跨时区旅行都绕不过计数，多端显示同一时间，卡内只有一种写法；无产品直接取证，属推断，按冲突裁决梯度中的一致性推出。必定义：账号所在时区的来源与修改后何时生效；本机时区与账号所在时区不同时，显示的时间是否附时区说明（可参考：附「（{时区}）」）。｜级别：可默认

## 必问状态（本模块专属，补充通用状态矩阵）
- 手势冲突：横滑回复与返回手势、列表左右滑与一级页切换、图片查看器内滑动是否冲突，各自优先级。
- 无障碍等价入口：每个手势操作的非手势入口是否已标明。
- 对方已拉黑 / 已注销 / 已退群：长按菜单中回复、转发、回应、通话等哪些项隐藏或置灰。
- 多端：菜单已打开时消息在另一端被撤回；多选进行中其中几条被撤回；另一端已读后本端角标何时更新。
- 离线与弱网：离线时哪些菜单项可用、撤销条在网络恢复后是否仍有效、加载超时后的重试次数上限。
- 消息已被转发或引用：原消息被撤回后，引用块与转发内容的呈现。
- 群与私聊差异：置顶、举报、撤回他人消息、@ 项的可用性按角色与会话类型逐项标明。
- 权限在操作中途被收回（被禁言、被降级、被移出群）：已打开的菜单与多选是否即时刷新，进行中的发送如何收尾。
- 确认弹窗打开期间：弹窗对象已被删除或已撤回时，点击主操作的结果与提示。
- 系统权限被拒（通知、相册、麦克风）：对应入口的空状态与「去系统设置」去向。
- 角标：清零时机（可见即读还是进入会话即清）、多端同步、静音计入、上限值。
- 多语言：RTL、德语、俄语等长文案语种下关键按钮与标题的截断策略。
- 减弱动态与大字号：开启后跳转高亮、发送动效、多选操作条的退化形态。

## 反模式
| 泛写/错写 | 正写 | 原因 |
|---|---|---|
| 操作完成后弹窗「操作成功」+「确定」 | toast「已{动作}」自动消失 | 仅告知不需要决定，不应打断 |
| 左滑删除既无确认也无撤销 | 删除给确认或限时撤销，至少其一（会话见 LIST-26，消息见 ACT-26） | 误触不可逆，违反可恢复 |
| 只写「支持滑动回复」 | 同时写等价入口（长按菜单「回复」） | 手势不能作为唯一入口 |
| 确认弹窗按钮写「确定 / 取消」 | 主操作写动词（「删除」），取消写「取消」 | 用户看不出将发生什么 |
| 错误提示「出错了，请重试」 | 写原因与可做的事，并给「重试」入口 | 泛词无法行动 |
| 断网弹窗阻断使用 | 常驻状态提示，输入仍可用；未发出消息的处理见 SEND-10 | 弹窗打断且无法恢复 |
| 不可用菜单项全部置灰保留 | 当前不可用的项直接隐藏 | 菜单冗长，用户无法理解为何灰 |
| 同一入口既有红点又有数字 | 二选一 | 语义重复 |
| 只写「显示未读数」，不写超限表现 | 写明超限表现（见 UX-D5）及三处是否同一规则（见 UX-22） | 超限必然出现，不写会撑破布局或各处读法不一 |
| 文案拼接「共」+ {N} +「条」 | 整句带变量并处理复数 | 多语言语序与复数不可拼 |
| 用颜色单独表达失败 | 图标加文字，颜色辅助 | 色弱与读屏用户无法感知 |
| 说明卡写「按钮 44 px、动画 300 ms」 | 写「点击热区满足平台无障碍标准；动效遵循减弱动态设置」 | 说明卡不写视觉规格 |

## 校准样例
最易写泛的是「消息长按菜单」。本例没有必问项：无发言权限时的菜单、各类型菜单项、撤回时限、常用表情数量、菜单顺序、删除后不给撤销都按推荐写成正文，卡内数值为示意，实际取值由业务定，并在交付稿「已按推荐默认」逐条列出。合格说明卡正文：

说明：
1. 长按一条消息，被长按的消息与背景分离，并进行以下判断以确定菜单项：
   a. 1-发言权限判断：当前用户在该会话是否有发言权限
      i. 无发言权限：最终不显示快捷回应条与「回复」，进入下一个判断
      i. 有发言权限：进入下一个判断
   a. 2-撤回状态判断：消息是否已被撤回
      i. 已撤回：只显示「仅自己删除」，不再进入后续判断
      i. 未撤回：进入下一个判断
   a. 3-发送状态判断：消息当前的发送状态
      i. 发送失败：只显示「重新发送」「删除」，「重新发送」排第一，不再进入后续判断
      i. 发送中：进入下一个判断，最终不显示快捷回应条与「转发」
      i. 已发送：进入下一个判断
   a. 4-消息类型判断：消息属于哪一类
      i. 一次性查看的消息：基础项为「回复」「选择」，进入下一个判断
      i. 文字：基础项为「回复」「复制」「转发」「选择」，进入下一个判断
      i. 图片/视频：基础项为「回复」「保存」「转发」「选择」，带文字说明时增加「复制」，进入下一个判断
      i. 文件：基础项为「回复」「保存」「转发」「选择」，进入下一个判断
      i. 语音：基础项为「回复」「转发」「选择」，进入下一个判断
      i. 位置、名片等其他类型：基础项为「回复」「转发」「选择」，进入下一个判断
   a. 5-归属判断：消息由谁发出
      i. 己方：增加「仅自己删除」；已发送且距发送未满 24 小时时增加「为所有人撤回」；判断结束，弹出菜单
      i. 他人：增加「举报」「仅自己删除」；判断结束，弹出菜单
2. 弹出快捷回应条与操作菜单：快捷回应条显示 6 个常用表情与「更多」入口；菜单只显示可用项，不可用的项隐藏
3. 菜单项顺序：回复、复制、保存、转发、选择、举报、仅自己删除、为所有人撤回
4. 点击「为所有人撤回」：弹窗提示：标题「为所有人撤回这条消息？」，正文「撤回后，会话中所有人看到的这条消息都将替换为撤回提示」，按钮「撤回」「取消」
5. 点击「仅自己删除」：弹窗提示：标题「仅自己删除这条消息？」，正文「删除后只影响自己，对方不受影响」，按钮「删除」「取消」；删除后不提供撤销
6. 注：「编辑」「信息」（回执详情）不在本卡范围，提供时另写说明并按第 3 条的顺序插入

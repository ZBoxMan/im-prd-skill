# 页面结构（主框架、会话列表、聊天页、输入栏、资料与设置页）

> 适用：画 IM 原型屏（一级页、会话列表、聊天页、输入栏、资料页、设置页）与写这些页面的说明卡时读。说明卡只写行为、结构、优先级，不写视觉规格；本文件的「量级」「时间窗」仅供判断取值是否离谱。证据见 evidence/11-ui-structure.md。
> 取证边界：本机客户端只取到静态字符串，没有实时界面；官方帮助中心只覆盖功能规则、几乎不描述界面布局。布局类结论以开源客户端源码为准，平台设计规范与开源 SDK 只作旁证、不计家数；按三档判定：五家中三家及以上直接证据一致的进基线，仅两家的进惯例（置信度中），仅一家的作分歧点。

## 基线（默认遵循，置信度高）

### 主框架与搜索
- **[UI-02] 搜索入口与结果分段**：搜索入口位于会话列表顶部；结果按「联系人与会话 / 消息记录」等类型分段，各有分段标题。必定义：可搜对象清单、分段顺序、占位文案（是否写明可搜范围）、无结果文案；最近搜索的保留与清除（见 MISC-03）；筛选维度与会话内按日期跳转（见 MISC-24）。｜置信度：高

### 会话列表
- **[UI-06] 已撤回的最后一条**：摘要显示撤回占位（区分己方与他人），不显示原文。必定义：占位文案；管理员撤回他人消息时占位是否带操作者名；若产品不留撤回痕迹，列表是否回退到上一条（见 05 模块）。｜置信度：高
- **[UI-07] 行内发送状态**：只对己方发出的最后一条显示；优先级：失败 > 发送中 > 已读 > 已送达 > 已发送；对方发来的最后一条不显示任何发送状态；气泡内的状态图标语义见 UI-39。必定义：对象被拉黑或回执关闭时是否仍显示已读态（与 UI-39 一致）。｜置信度：高
- **[UI-09] 置顶**：见 LIST-01（上限、超限提示、付费档与置顶区顺序只在该处定义）；本模块只补：置顶会话与普通会话在列表上有可辨识的区分。｜置信度：高（同 LIST-01）
- **[UI-12] 长按菜单与滑动动作集合**：会话级操作集合高度一致：标为已读/未读、置顶/取消置顶、静音/取消静音、归档或折叠、删除。必定义：菜单项顺序（删除类是否置于最后并用破坏性样式）；滑动动作构成（见 UI-D5）及每个滑动动作在长按菜单中是否有等价入口；静音时长档位；是否提供多选，多选操作条构成与删除前的确认文案。｜置信度：高
- **[UI-13] 归档与折叠入口**：归档或折叠的会话收起为会话列表中的一行入口。必定义：入口位置（列表顶部或底部）及是否参与普通排序；入口上数量的口径（归档会话总数，或仅有未读的归档会话数；有未读 @ 时是否改显示 @ 标识）；进入后的返回文案；新消息是否让会话回到主列表见 LIST-23。｜置信度：高
- **[UI-14] 陌生人会话入口**：未接受的陌生人会话或消息请求带明确的请求态（独立入口、会话标签或会话顶部横幅）；该会话落在主列表还是独立入口见 03 模块的陌生人落点分歧。必定义：请求态的呈现位置与文案；提供的处理动作（接受、删除、屏蔽、举报）；接受前受限的能力；请求态会话的通知预览是否展示正文见 NOTI-24（必问）。｜置信度：高

### 聊天页
- **[UI-22] 系统消息**：文案用第三人称，己方用第二人称变体（「你撤回了一条消息」「{昵称} 撤回了一条消息」）。必定义：展示形态（是否居中、无气泡、无头像、无已读状态、不可回应、不可 @、无长按菜单）；入时间线的事件清单（权限变更、加入规则等低层状态事件是否入时间线）；事件对哪些角色可见（如退群提示只对管理员可见）；连续入群与退群事件、连续被删除消息是否折叠及折叠阈值。｜置信度：高
- **[UI-23] 内容类型模板**：文本、图片或视频缩略图、语音、文件、位置、名片、贴纸、链接预览、投票、通话记录等内容类型各有独立展示；版本不支持的类型显示兜底文案。必定义：逐类展示要素（语音：时长与播放态；文件：名称、大小、状态；链接预览：标题、摘要、缩略图、整卡是否可点、获取失败的占位文案）；链接预览发送前是否在输入栏上方显示可移除的预览条；兜底文案与是否引导升级（见 MISC-17）。｜置信度：高
- **[UI-24] 引用块**：回复消息带引用块，含被引用人与内容摘要；点击引用块跳转原消息。必定义：引用块位置（气泡内正文上方或气泡外）；各类型的摘要形态（文本截断、图片缩略图、语音时长）；跳转后落点是否短暂高亮；原消息不在已加载范围时如何跳转；原消息已撤回或不存在时的文案与点击行为；限时消息到期后被引用的原文是否仍显示。｜置信度：高
- **[UI-25] 进入会话的定位**：有未读 → 滚到第一条未读并在其上方显示未读分割线；无未读 → 停在最新消息。必定义：分割线文案（是否带数量）、分割线何时消失；定位完成前是否暂不把消息标为已读。｜置信度：高
- **[UI-27] 跳到底部与跳到 @**：上滑浏览历史后出现「回到底部」入口；有未读 @ 时另出现独立的「跳到 @」入口。必定义：「回到底部」出现的滚动阈值、是否显示新消息数；多条未读 @ 时的跳转顺序、落点是否高亮、入口何时消失。｜置信度：高
- **[UI-28] 失败重试入口**：发送失败的消息在气泡旁显示失败标识；失败态用状态图标表达，不让整个气泡变色。必定义：点击失败标识后的处理（直接重发，或弹出「重新发送 / 删除」）；长按菜单是否同时提供「重新发送」及其位置。｜置信度：高
- **[UI-39] 气泡回执图标**：己方消息气泡用独立图标表达发送中、已发送、已送达或已读、失败，每态一个图标，层级数与是否含「已送达」跟随回执层级裁决（见 SEND-09）；已送达与已读的区分遵循 UX-28。必定义：各态图标语义与读屏文案；语音是否有「已播放」态；群聊已读口径（任一人或全员）与是否可展开详情；关闭回执或对方被拉黑后的显示；己方消息被编辑后已读态是否重置。｜置信度：高

### 输入栏
- **[UI-31] 草稿**：离开会话保存未发送文字，回到会话时恢复；草稿的保存、恢复、清除时机与覆盖确认只在本条定义，会话列表的草稿标识见 LIST-05。必定义：退出应用后是否保留；草稿清除时机（如发送成功后）；关闭编辑态且内容非空时是否确认放弃；已有草稿被覆盖前是否确认及确认文案；非文字草稿的保存范围；跨设备同步见 MISC-32。｜置信度：高

## 惯例（可默认，标建议）

### 主框架与搜索

- **[UI-01] 一级导航**：底部一级入口 3 至 5 个，每个入口同时有图标与单词标签；一级页没有返回键，二级页顶栏有返回并支持系统边缘返回；不用「更多」承载高频入口。必定义：入口清单与顺序、默认落点、哪些入口带角标、再次点击当前入口的行为。｜量级：3–5 个｜置信度：中（入口数量仅一家产品直接取证，图标加标签、返回规则与不用「更多」依据平台设计规范旁证）

### 会话列表

- **[UI-03] 行构成**：头像 → 第一行（会话名单行截断 + 状态图标 + 时间）→ 第二行（摘要截断 + 标识区）。长文字一律省略，不换行撑高行。必定义：摘要行数（1 行或 2 行）；标识区能并列哪些标识及其顺序（见 UI-08）。｜量级：摘要 1–2 行｜置信度：中（行构成两家直接证据；摘要行数只有一家源码加开源客户端旁证，已移入必定义）
- **[UI-04] 摘要内容优先级**：有本地草稿时摘要显示草稿，优先于最后一条消息。必定义：搜索态命中片段、对方正在输入、已撤回占位、系统消息或通话记录与普通消息预览之间的完整优先级（可参考：命中片段 > 正在输入 > 草稿 > 撤回占位 > 系统消息或通话记录 > 普通消息）；输入中结束后回到哪一级；每一级的展示文案。｜置信度：中（草稿优先于最后一条有三家直接证据；输入中覆盖摘要与完整顺序只有一家证据加开源 SDK 旁证，含推断，已移入必定义）
- **[UI-15] 列表空状态**：筛选无结果与搜索无结果使用各自独立文案，不复用「无会话」空状态。必定义：无任何会话时的空状态构成（标题、说明、主操作如「发起聊天」）；筛选空状态是否带「编辑筛选」入口。｜置信度：中（仅两家直接证据；无会话空状态构成仅开源客户端旁证）
- **[UI-08] 未读与 @ 标识**：未读数字与 @ 标识可并列；静音会话的未读呈现见 UX-23。必定义：数字上限（见 UX-D5）、@ 与「@所有人」是否区分文案；总未读恰为 1 条且该条是 @ 时是否只显示 @ 标识；多种标识（通话中、静音、@、未读数、置顶图钉）并存时的顺序与取舍。｜置信度：中（@ 与未读并列两家直接证据；标识顺序只有一家加开源客户端旁证，已移入必定义）

### 聊天页

- **[UI-16] 顶栏**：标题显示对方名或群名，副标题显示实时状态（连接中、正在输入、在线或最近在线）。必定义：右侧入口构成（通话、搜索、更多）；点击标题区的去向；群标题是否含成员数；副标题各状态的优先级与文案；隐私设置关闭后副标题显示什么。｜置信度：中（副标题实时状态两家直接证据，另一家位置为推断；入口构成与状态优先级只有一家证据，只在必定义）
- **[UI-18] 消息分组与打断**：同一发送者连续消息合并成一组；跨日、换发送者、超过时间窗时打断分组。必定义：时间窗（见 UI-D2）；其他打断条件（中间插入系统消息、定时消息、带回应的消息、转发消息按原作者还是转发人判断）。｜量级：3–10 分钟｜置信度：中（仅两家直接证据）
- **[UI-17] 置顶消息条**：顶栏下方常驻展示置顶消息，点击跳转原消息；多条置顶时可切换并显示序号或数量。必定义：置顶条能否隐藏；上限与满额策略见 ACT-21；有效期见 ACT-23；谁有权置顶、是否通知成员见 ACT-22；发送中的消息能否置顶；置顶时是否在会话内留系统消息说明谁置顶。｜置信度：中（顶栏常驻与多条切换仅两家直接证据，另有开源客户端旁证）

### 输入栏

- **[UI-30] 输入长度与增高**：输入超过发送长度上限时给明确文案（「文字过长，无法发送」）。必定义：长度上限；输入框是否随内容增高、增高上限及超出后是否框内滚动。｜量级：约 5 行｜置信度：中（长度超限提示仅两家直接证据；增高规则仅开源 SDK 旁证）
- **[UI-32] 回复与编辑横条**：回复态：输入框上方出现引用条（被引用人 + 摘要 + 关闭），点关闭取消回复；编辑态：出现「编辑消息」横条，原文预填。必定义：点引用条本身是否跳转原消息；编辑态发送按钮文案；取消编辑后是否恢复编辑前的草稿；有改动时取消是否确认。｜置信度：中（回复与编辑横条两家直接证据，另一家有引用面板佐证；必定义里的细节各只有一家证据）
- **[UI-33] @ 面板**：群聊中输入 @ 弹出成员选择，选中后插入 @ 昵称。必定义：继续输入是否过滤；插入后是否作为整块、退格是否整块删除；单聊是否触发；@所有人的权限（可按群人数门槛限制为仅管理员）与入口位置。｜置信度：中（仅两家直接证据，面板细节仅开源 SDK 旁证）

### 资料页与设置页

- **[UI-34] 资料页分组**：头部为头像、名称与主操作（发消息、通话等），其下为个人信息字段、共享内容（媒体、文件、链接）、会话设置（通知、置顶、消息保留时间）、（群）成员、危险区等分组。必定义：分组顺序；各分组是否显示的条件。｜置信度：中（仅两家直接证据，顺序为推断）
- **[UI-36] 群资料的权限入口**：管理型分组（成员管理、权限、邀请链接、入群申请）只对有权限者出现；管理员以标签标识。必定义：无权限入口隐藏还是置灰并说明原因；不可被移出的角色在成员操作中是否出现「移出」。｜置信度：中（管理型分组按权限出现有四家直接证据，管理员标签两家；隐藏或置灰只有一家证据，只在必定义）
- **[UI-37] 设置页一级分组**：账号与资料、通知、隐私与安全、数据与存储（自动下载、存储用量、清理缓存）、通用（外观、语言）、关于与帮助；「退出登录」与「清空全部聊天记录」等危险项置底并确认。必定义：分组顺序与二级页清单。｜置信度：中（三家分组有交集，顺序未确认）
- **[UI-38] 设置项交互**：开关即时生效，无「保存」按钮；需要选择的设置进二级页并在右侧显示当前值。必定义：哪些设置项需在项下方补一句后果说明（开启后会改变对方可见内容或设备行为的）。｜置信度：中（开关即时生效、二级页选择各两家直接证据加平台规范旁证；后果说明仅一家）
- **[UI-35] 危险操作置底**：屏蔽、举报、退出群聊、删除聊天、删除联系人集中在页面最底部独立分组，文案为动宾短语，每项点击后确认（确认规则见 UX-11、UX-12）。｜置信度：中（置底仅一家直接取证加平台设计规范旁证；动宾文案与点击后确认有三家）

## 分歧点（必问的问 Box，可默认的按推荐写并列清单）
- **[UI-D1] 一级导航构成**：A 会话／通讯录／我（3 项）；B 会话／通讯录／发现或动态／我（4 项，国内主流）；C 会话／通话／设置（极简，隐私优先类）。推荐：A，理由：用户理解（无内容流功能时不放空入口），一级入口只放高频；三项结构与已取证产品的入口构成均不同，属用户理解取舍。｜级别：可默认
- **[UI-D2] 分组时间窗**：A 约 3 分钟；B 约 10 分钟；C 约 1 分钟；D 不设时间窗，只按发送者连续。推荐：A，理由：用户理解（时间戳不过密也不过疏）。｜级别：可默认
- **[UI-D3] 头像与昵称显示节奏**：A 头像在组尾、昵称在组首；B 每条消息都显示头像与昵称（部分国内产品）；C 头像在组首。推荐：A，理由：用户理解，与分组规则一致；头像在组尾有两家源码取证。｜级别：可默认
- **[UI-D4] 会话列表时间风格**：A 相对时间（「3 分钟前」）；B 绝对时间（当天时刻 / 昨天 / 星期 / 日期）。推荐：B，理由：用户理解（国内用户习惯，读屏仍可读完整时间）；与唯一有源码证据的产品做法（A）相反，属用户理解取舍。｜级别：可默认
- **[UI-D5] 会话行滑动动作构成**：A 单动作「归档」，全滑执行；B 左右各露 2–3 项（右滑已读 + 置顶，左滑静音 + 删除 + 归档）；C 仅左滑，露「置顶 / 标未读 / 删除」。推荐：B，理由：可恢复（删除必带确认或撤销）且动作集合与长按菜单一致。｜级别：可默认
- **[UI-D6] 归档会话来新消息**：见 LIST-23（只在该处定义）。
- **[UI-D7] 输入栏被限制（禁言、已退群、已屏蔽）时的形态**：A 整条输入栏替换为说明文字或唯一动作按钮（解除屏蔽、重新加入）；B 保留输入栏，点发送后用弹窗或系统消息提示。推荐：A，理由：无障碍与可恢复（用户一眼知道原因与可做的事）。｜级别：可默认
- **[UI-D8] 超长消息展示**：A 超过显示上限折叠并显示「阅读更多」，点击进全文页；B 不折叠，全文显示；C 折叠后原地展开。推荐：A，理由：用户理解（长文不占满屏）；此项仅单一来源取证。｜级别：可默认
- **[UI-05] 摘要前缀与类型占位**：见 LIST-28（群聊发送者名前缀与己方「你：」前缀）、LIST-05（草稿标识）、LIST-06（类型占位与不支持消息的兜底占位）。
- **[UI-10] 排序**：见 LIST-20（排序主键与草稿影响只在该处定义）。
- **[UI-19] 气泡时间戳与昵称显示条件**：本轮仅一家源码直接取证（低置信度）。选项 A：气泡内时间只在组尾显示，发送中、发送失败、带过期倒计时的消息必显；发送者昵称只在多人会话显示／选项 B：每条消息都显示时间，发送者昵称只在多人会话显示。推荐：A，理由：用户理解——同组内不重复时间戳，异常态仍可见。取舍背景：单聊不显示昵称为普遍做法但未逐家取证；头像与昵称的位置见 UI-D3。｜级别：可默认
- **[UI-20] 日期分隔条分级**：本轮仅一家源码直接取证（低置信度）。选项 A：跨日插入，今天、昨天、一周内显示星期、更早显示完整日期（跨年带年份）／选项 B：跨日插入，今天、昨天、半年内显示星期加月日、更早显示含年份的完整日期。推荐：A，理由：用户理解——一周以外的星期对定位帮助小；与唯一有证据的产品做法（B）相反，属用户理解取舍。取舍背景：滚动时顶部浮出当前日期仅一家源码加开源客户端旁证，需要时作为未决项问 Box。｜级别：可默认
- **[UI-21] 气泡方向**：本轮仅一家源码直接取证（低置信度）。选项 A：己方靠右、对方靠左，RTL 语言下整体镜像（见 UX-31）／选项 B：全部靠左，以头像与昵称区分发送者。推荐：A，理由：用户理解——一眼区分己方与对方；选项 B 本轮无产品取证。｜级别：可默认
- **[UI-29] 输入栏构成**：本轮仅一家源码直接取证（低置信度）。选项 A：附件入口 → 多行输入框（含表情入口）→ 右侧「语音 / 发送」互斥按钮，输入框为空显示语音、有内容显示发送／选项 B：语音入口与发送按钮分设，语音为独立按钮或独立模式切换。推荐：A，理由：用户理解——入口少、主操作随输入状态切换。取舍背景：另一家桌面端有独立的「发语音」入口；附件菜单项清单与顺序、语音按住与锁定规则无论选哪项都需写明（见 06 模块）。｜级别：可默认
- **[UI-11] 列表时间分级**：选项 A：越近越精确、越远越粗（当天时刻、昨天、星期、日期），跨年必须带年份／选项 B：统一显示完整日期与时刻。推荐：A，理由：用户理解——近期消息看时刻、久远消息看日期最省读；取舍背景：只有一家源码直接取证，另两家只有今天、昨天、星期、年份类时间词，用途未确认。选 A 时必定义：分级档位（与 UI-D4 一致）；12 或 24 小时制与星期、日期顺序是否跟随系统与语言区域；读屏是否读完整时间。｜级别：可默认
- **[UI-26] 阅读位置保护**：选项 A：用户停在底部时新消息自动滚入；已上滑浏览历史时新消息不抢滚动位置，改为在「回到底部」入口上累计提示／选项 B：新消息到达时总是滚到底部。推荐：A，理由：用户理解——阅读历史时不被打断；取舍背景：一家源码直接取证，另三家只有新消息计数与回到底部类字符串，行为为推断。选 A 时必定义：用户拖动列表时新到消息是否暂存至停止滚动后再插入；加载更早历史后是否保持当前阅读位置。｜级别：可默认

## 必问状态（本模块专属，补充通用状态矩阵）
- 对方已拉黑 / 已注销：会话行名称、头像、摘要、状态图标、聊天页输入栏分别如何呈现。
- 对方已退群 / 被移出群 / 群已解散：会话行是否保留、聊天页输入栏是否替换、历史是否可读。
- 多端：另一台设备已读后，本端未读数、分割线、@ 标识是否同步清除；另一端已撤回，本端列表摘要与引用块如何更新。
- 离线接收方 / 发送方离线：列表与聊天页的发送中状态保留多久、转失败的条件。
- 弱网与断网：列表顶部与聊天顶栏状态文案（见 UX-15）；加载历史超时如何呈现。
- 消息已被转发或引用后原消息被撤回：引用块与转发卡片显示什么。
- 群与私聊差异：昵称、@、已读呈现、摘要前缀、置顶权限逐项标明。
- 权限在操作中途被收回（输入中被禁言、被移出群、管理员被降级）：草稿是否保留、输入栏何时替换、已打开的菜单是否刷新。
- 草稿与排序：有草稿是否改变会话排序、是否影响置顶会话位置。
- 回执：关闭已读回执、对方被拉黑、群聊部分人已读时，气泡与列表的状态图标分别显示什么；己方消息被编辑后状态图标是否重置。
- 超限：置顶上限、附件数量与大小上限、输入长度上限，各自的提示与去向。
- 空会话与首次进入：无消息的新会话显示什么引导；进入已清空历史的会话时分割线与定位如何处理。
- 版本过低：不支持的消息类型在列表、聊天页、通知中各显示什么占位。

## 反模式
| 泛写/错写 | 正写 | 原因 |
|---|---|---|
| 「会话列表显示最后一条消息」 | 写明摘要优先级、前缀、类型占位、撤回占位 | 列表摘要有 6 级来源，泛写会漏草稿与输入中 |
| 已撤回消息的摘要仍显示原文 | 显示撤回占位 | 泄露已撤回内容，违反隐私与数据完整 |
| 未读数显示完整数字（如 1234） | 超过上限显示「{N}+」 | 撑破行内标识区，也无阅读价值 |
| 进入会话一律滚到最底部 | 有未读定位到第一条未读并显示分割线 | 用户找不到从哪读起 |
| 新消息到达时强制滚到底部 | 用户不在底部时不抢位置，累加到「回到底部」 | 打断正在阅读历史 |
| 失败重试只放在长按菜单 | 气泡旁显示失败标识，点击可处理 | 用户发现不了入口 |
| 系统消息带头像与气泡、可长按回应 | 居中无气泡，无菜单 | 与用户消息混淆 |
| 危险操作与普通项混排或放在中间 | 置底独立分组，动宾短语 | 误触不可逆操作 |
| 无权限者点击入口后才提示「无权限」 | 入口隐藏或置灰并说明原因 | 浪费一次点击且无法恢复 |
| 设置项开关后还要点「保存」 | 开关即时生效 | 与平台设置习惯冲突 |
| 已送达与已读只靠勾的颜色区分 | 形状或数量不同，读屏读出「已送达」「已读」 | 色弱与读屏用户无法区分 |

## 校准样例
最易写泛的是「会话列表行摘要」。本例没有必问项：摘要优先级、发送者前缀、撤回占位与非文字草稿都按推荐写成正文，并在交付稿「已按推荐默认」逐条列出。合格说明卡正文：

说明：
1. 适用范围：会话列表每一行的摘要区（第一行为会话名、状态图标与时间，第二行为摘要与标识区）
2. 触发：列表刷新或会话有新活动时，按以下顺序判断摘要内容，命中即停：
   a. 1-搜索态判断：当前是否处于搜索结果态
      i. 是：摘要显示命中关键词所在的片段
      i. 否：进入下一个判断
   a. 2-输入状态判断：对方是否正在输入
      i. 是：摘要显示「正在输入…」，对方停止输入后回到下一个判断
      i. 否：进入下一个判断
   a. 3-草稿判断：本会话是否有未发送草稿
      i. 有：摘要显示「草稿：」加草稿正文；非文字草稿显示「草稿：」加类型占位，如「草稿：[图片]」
      i. 无：进入下一个判断
   a. 4-撤回判断：最后一条消息是否已撤回
      i. 己方撤回：摘要显示「你撤回了一条消息」
      i. 他人撤回自己的消息：摘要显示「{昵称} 撤回了一条消息」
      i. 管理员撤回成员消息：摘要显示「{管理员昵称} 撤回了一条成员消息」
      i. 未撤回：进入下一个判断
   a. 5-类型判断：最后一条消息的类型
      i. 系统消息或通话记录：显示系统文案
      i. 非文字内容：显示类型占位「[图片]」「[视频]」「[语音]」「[位置]」「[名片]」；当前版本不支持的类型显示「[当前版本不支持此消息]」
      i. 文字：显示正文，最多 2 行，超出以省略号截断
3. 发送者前缀：群聊中对方发出的消息加「{发送者名}：」前缀，类型占位同样带前缀，如「{发送者名}：[图片]」；群聊中己方发出的消息加「你：」前缀；单聊不加前缀；草稿、撤回占位与系统消息不加前缀

# 会话列表（功能规则）

> 适用：会话排序、置顶、免打扰、归档/折叠、标为未读、草稿与摘要前缀、删除/清空会话、会话分组、未读计数的 PRD 需求。页面行的视觉层级与元素排布参见 11-ui-structure.md，本文件只管功能规则。证据见 evidence/03-chat-list.md。

## 基线（默认遵循，置信度高）
- **[LIST-01] 置顶**：会话可置顶与取消置顶，置顶会话固定在列表最上区域；置顶数量有上限。必定义：上限数 {N}；超限时的处理（拒绝并提示，或其他做法）及提示文案与载体；置顶区内顺序（按置顶时间或可手动调整）；单聊与群聊是否共用上限；多端置顶是否同步；置顶是否有有效期（见 LIST-30）；付费档到期后超出免费上限的置顶见 PTS-25。｜量级：免费档 3 至 5 个，付费档 10 至 20 个｜置信度：高
- **[LIST-02] 免打扰**：单个会话可设免打扰；免打扰期间的提醒与未读规则见 NOTI-04。必定义：入口位置；列表行如何呈现免打扰状态；免打扰对 @我 的穿透见 NOTI-20，对来电的影响见 NOTI-30；免打扰会话未读是否计入总角标见 NOTI-26；免打扰状态是否对会话对方可见。｜量级：—｜置信度：高
- **[LIST-03] 归档/折叠不删数据**：把会话收进归档或折叠区不删除聊天记录；主列表保留该区的独立入口，被收纳会话可经入口找回。必定义：入口位置；入口是否显示数量及口径（会话数或有未读的会话数）；能否经搜索找回；能否手动移出；收纳区内是否仍可置顶；批量收纳的反馈文案。｜量级：—｜置信度：高
- **[LIST-04] 标为未读与已读**：会话菜单提供「标为未读」「标为已读」。必定义：无新消息的会话被标为未读时列表的呈现（有无数字）；该标记计入未读总数与角标的口径；标记的清除条件；多端是否同步。｜量级：—｜置信度：高
- **[LIST-06] 摘要类型占位**：非文本消息（含一次性媒体）在摘要中用类型占位文案，不展示原内容。必定义：每种消息类型的占位文案；一次性或阅后即焚内容是否另用专门占位；通话记录、版本不支持消息的摘要文案；服务类/官方会话的来源标记文案。｜量级：—｜置信度：高
- **[LIST-07] 未读 @我 标识**：群会话中有未读的 @我 消息时，列表行有独立于未读数的 @ 标识。必定义：@全体 是否使用同一标识（见 NOTI-21）；被回复是否使用同一标识（见 NOTI-22）；多条 @ 的逐条跳转；标识清除条件。｜量级：—｜置信度：高
- **[LIST-08] 删除会话与清空记录是两件事**：「删除会话」让会话从列表消失且本机记录一并清空；「清空聊天记录」保留会话入口、只清记录；两者默认只作用于本账号，对方的记录不受影响（是否提供双方清空见 LIST-25）。必定义：两个入口的位置与确认文案；确认弹窗或限时撤销（见 LIST-26）；会话内有未处理款项时的拦截见 PAY-26；本账号多端是否同步删除。｜量级：—｜置信度：高

## 惯例（可默认，标建议）

- **[LIST-05] 草稿显示**：有未发送内容的会话，列表摘要处以「草稿」标识加草稿内容替换最后一条消息摘要；草稿的保存、恢复与清除时机见 UI-31。必定义：标识文案；非文本草稿（图片、语音、引用、位置等）的摘要占位文案；草稿是否影响排序（见 LIST-20）；草稿跨设备同步（见 MISC-32）。｜量级：—｜置信度：中（草稿标识有三家直接证据；非文本草稿占位只有一家证据，已移入必定义）
- **[LIST-10] 未读数展示**：会话行展示未读条数；截断上限见 UX-D5，免打扰会话的未读呈现见 UX-23。必定义：@ 未读与普通未读是否分别计数；未读数清零时机（进入会话即清零或滚动到底后清零）。｜量级：—｜置信度：中（会话行展示未读数有四家直接证据；截断与免打扰区分呈现已改由归属条目定义）
- **[LIST-28] 群会话摘要带发送者名**：群会话的最后一条消息摘要前加「{发送者名}：」前缀。必定义：己方发出的最后一条是否加「你：」前缀；发送者名取群昵称还是账号昵称；类型占位是否同样带前缀（如「{发送者名}：[图片]」）；系统消息是否带前缀。｜量级：—｜置信度：中（两家客户端字符串直接证据，均为中置信：一家列表行无障碍朗读含「来自：发送者」，一家摘要格式为发送者前缀加类型占位；己方「你」前缀与类型占位带前缀各只有一家证据，已移入必定义）

## 分歧点（必问的问 Box，可默认的按推荐写并列清单）
- **[LIST-20] 排序与草稿**：本轮对排序算法与草稿影响均未取到直接证据（低置信度）。选项 A：置顶优先，其余按最后一条消息时间倒序，草稿不影响排序／选项 B：同 A，但有草稿的会话按草稿保存时间参与排序／选项 C：同 A，另把有未读 @我 的会话提到置顶区之下。推荐：A，理由：用户理解——排序只受消息时间影响最可预期，且草稿若参与排序会使多端顺序不一致。会话列表广告条目不参与会话排序，见 ADS-07。｜级别：可默认
- **[LIST-21] 免打扰时长**：选项 A：仅开/关，持续到手动关闭／选项 B：固定档位（小时级、天级、永久），到期自动恢复，列表显示截止时间／选项 C：在 B 基础上增加自定义截止时间。推荐：B，理由：无障碍与可恢复——到期自动恢复，避免永久静音导致漏看。量级：最短一小时，最长约一周，另有「永久」，档位 3 至 7 档。取舍背景：档位制在 3 家出现、另 2 家仅开关，故不进基线。｜级别：可默认
- **[LIST-22] 群消息提醒档位**：选项 A：群与单聊共用同一免打扰开关／选项 B：群独立四档（接收并提醒、接收不提醒、收入收纳区且不提醒、屏蔽）。推荐：A，理由：隐私与数据完整——「屏蔽」档使消息不被接收，与历史完整性冲突，其余档位可由免打扰加归档组合实现。群单独静音来电不在本条，见 NOTI-30。｜级别：可默认
- **[LIST-23] 已归档会话来新消息**：选项 A：一律移回主列表／选项 B：仅未免打扰的移回，免打扰的留在归档／选项 C：默认留在归档，由用户设置项决定是否移回。推荐：B，理由：无障碍与可恢复——未免打扰的消息不会被漏掉，免打扰的不打扰用户。取舍背景：四家做法分属 A、B、C，无一致做法。｜级别：可默认
- **[LIST-24] 陌生人新会话落点**：接触模型（能否直接发消息、是否先进消息请求）见 REL-21；本条只管消息请求类会话在列表中的位置。选项 A：进主列表并带「消息请求」状态，接受前能力受限／选项 B：自动收入归档并免打扰，可在设置关闭／选项 C：与普通会话同等进入主列表。推荐：A，理由：用户理解——陌生人消息不被藏起来，同时与 REL-21 的接触模型一致。｜级别：可默认
- **[LIST-25] 双方清空或双方删除**：选项 A：仅本方，对方记录不受影响／选项 B：私聊可选「同时为对方清空」，群创建者可「为所有成员删除」。推荐：A，理由：隐私与数据完整——不允许单方抹除对方持有的记录。｜级别：必问
- **[LIST-26] 删除防误触**：选项 A：二次确认弹窗，无撤销／选项 B：无确认，删除后限时提供「撤销」提示／选项 C：确认弹窗加限时撤销。推荐：A，理由：用户理解——清空记录不可恢复时确认弹窗最可预期；删除前确认有两家直接证据，限时撤销仅一家有直接证据。｜级别：可默认
- **[LIST-27] 会话分组**：选项 A：不做自定义分组，只有主列表与归档／选项 B：内置筛选（如仅未读）／选项 C：自定义文件夹或列表（含包含/排除规则、数量上限，删除分组不删会话，可整体静音）。推荐：A，理由：用户理解——国内主流产品以折叠或归档代替分组；自定义分组需另定数量上限与多端同步规则，且 3 家有（其中两家证据置信度中）而 2 家无，不进基线。量级：文件夹数十个以内，每个文件夹手选会话上限约百至数百。｜级别：可默认
- **[LIST-29] 全部标为已读**：选项 A：提供，且二次确认／选项 B：不提供。推荐：B，理由：隐私与数据完整——仅一家有直接证据且该家提供，推荐 B 与现有产品做法相反，属防误触取舍：批量清未读易误触并丢失重要未读提示。｜级别：可默认
- **[LIST-30] 置顶有效期**：选项 A：置顶无有效期，手动取消／选项 B：置顶时选择时长，到期自动取消置顶（档位另定）。推荐：A，理由：用户理解——仅一家有直接证据，到期自动取消会让置顶状态与用户预期、多端显示产生偏差，需另定到期提示与同步规则；置顶消息的时长另见 05-message-actions.md。｜级别：可默认
- **[LIST-31] 锁定会话**：选项 A：不做／选项 B：会话可锁定，进入需额外验证（设备验证或自设代码）并收进隐藏入口；锁定会话的通知不显示发送者与内容（见 NOTI-33）；设备锁屏后自动重新锁定；忘记代码时「解锁并清除」会同时清空锁定会话内的消息。推荐：A，理由：隐私与数据完整——仅一家有直接证据且该家提供，推荐 A 与现有产品做法相反，属数据完整取舍：「忘记代码即清空消息」与数据完整冲突，须单独设计恢复路径。｜级别：可默认
- **[LIST-09] 仍在群中时删除群会话**：选项 A：只能「删除并退出」或先退群再删除，不存在会话已删、成员身份仍在的状态／选项 B：允许只把群会话从列表删除或隐藏、保留成员身份，有新消息时会话重新出现。推荐：A，理由：用户理解——状态最少，不会出现「列表里没有、却仍在群里收消息」的隐身成员状态。取舍背景：A 有三家直接证据；一家国内主流产品为 B（隐藏的会话有新消息时重新显示），面向国内用户时 B 更贴近习惯。选 B 时须另定：删除时是否清空本机记录、重新出现后历史是否可见、@我 是否让会话重新出现、群主/创建者的额外选项（见 07-groups-channels.md）。｜级别：必问

## 必问状态（本模块专属，补充通用状态矩阵）
- 对方已拉黑/已注销/已退群：会话是否保留在列表；摘要显示什么；能否置顶、免打扰、删除。
- 群已解散或本人被移出群：会话保留为只读还是自动消失；置顶与免打扰状态是否保留；仍有未读 @ 时如何清除。
- 多端：另一台设备已置顶、已归档、已删除、已标为未读时，本机列表何时、如何更新；两台设备同时置顶导致超限时以谁为准。
- 离线接收方：离线期间收到的消息恢复在线后，排序按服务端时间还是本机接收时间；未读数是否一次性补齐。
- 最后一条消息被撤回、被删除或被对方编辑：摘要显示什么；排序是否变化；未读数是否回退。
- 置顶已满：再置顶的提示与去向；多端并发超限。
- 免打扰到期：到期瞬间已有的未读如何呈现；到期是否有提示。
- 已归档会话收到 @我、被回复或来电：是否仍提醒、是否回到主列表。
- 草稿与发送失败消息并存：摘要优先显示哪一个。
- 草稿所在会话被删除、被清空：草稿是否一并清除。
- 弱网或首次加载：列表加载态、同步中的置顶与未读是否先显示本机缓存。
- 若有话题或回复线程：串内未读、@我 与静音口径见 FEED-39（是否提供消息级回复线程见 FEED-40）。
- 备份恢复后：此前已删除的会话或已清空的记录是否重现；仅早于删除时刻的备份才可能带回。
- 置顶带有效期时（若选 LIST-30 的 B）：到期瞬间列表如何呈现、多端是否同步、是否提示。
- 锁定会话（若选 LIST-31 的 B）：锁定后会话在列表与搜索中的可见性、摘要与通知显示什么、换新设备后是否仍锁定、锁定会话的来电是否照常。
- 消息已被转发或引用后原会话被删除：引用卡片显示什么。

## 反模式
| 泛写/错写 | 正写 | 原因 |
|---|---|---|
| 「会话按时间排序」 | 写明主键（置顶优先、再最后一条消息时间倒序）、草稿/撤回是否影响排序、时间取服务端还是本机 | 多端顺序不一致，撤回后排序无定义 |
| 「置顶会话」不写上限 | 写明上限 {N}、超限提示、多端并发超限处理 | 无上限使置顶区失效，并发时多端冲突 |
| 「免打扰后不再收到消息」 | 免打扰只静默提醒，消息与未读照常累计 | 与归档、屏蔽混淆，造成数据丢失预期 |
| 「删除会话」不区分清空记录 | 分别定义删除会话、清空记录、删除并退出，并写各自确认文案与是否可恢复 | 用户无法预期记录是否保留 |
| 「归档后有新消息自动回主列表」 | 按 LIST-23 的裁决分免打扰与非免打扰 | 免打扰会话被打扰，或重要消息被漏掉 |
| 「显示未读数」 | 写截断阈值、@ 未读是否单独、免打扰会话的未读呈现、清零时机 | 数值口径不明，角标与列表对不上 |
| 「草稿显示在列表」 | 写标识文案、非文本草稿占位、发送后清除、是否跨设备同步 | 草稿残留或丢失无定义 |
| 「删除会话时对方也会删除」 | 默认仅本方；若做双方清空，须单独裁决并写对方侧提示 | 隐私与数据完整冲突 |

## 校准样例
最易写泛的功能：「置顶」。点击前只有「是否已达上限」一个前置校验，不起判断链。本例没有必问项：置顶上限、新置顶的位置、多端同步都按推荐写成正文，卡内数值为示意，实际取值由业务定，并在交付稿「已按推荐默认」逐条列出。

说明：
1. 会话未置顶时，会话菜单显示「置顶」；已置顶时显示「取消置顶」
2. 点击「置顶」，当前置顶数已达 5 个时：toast 提示：「最多置顶 5 个会话」，会话保持原位，置顶区不变
3. 当前置顶数未达上限时：会话移到置顶区首位，菜单项变为「取消置顶」，无提示
4. 点击「取消置顶」：会话移出置顶区，回到普通区并按会话排序规则就位，无提示
5. 置顶与取消置顶同步到本账号已登录的所有设备；多台设备同时置顶导致超出上限时，以服务端先收到的操作为准，后到的设备撤回该次置顶并 toast 提示：「最多置顶 5 个会话」

## 工作地点

- 原型、说明卡、标注：直接在目标 design 文件画布上做。
- **技术流程图与功能清单：先在 FigJam 白板 `<FigJam 白板 fileKey>` 做好，再复制粘贴回原型 PRD**（Plugin API 在 design 模式禁用 TABLE / CONNECTOR / SHAPE_WITH_TEXT）。

## 页面骨架

大区自上而下排列，区间 y 轴留 ≥1500px。**口径：上区最下一排原型帧的底沿 → 下区一级标题条顶沿。**说明卡列不计入该口径，但**卡列本身不得与下区标题条相交**——说明卡是 HUG 高度，每次改正文都会变高，重排后必须跑顶层 AABB 归零。

**一级标题条**（每个大区一条）
- 图层名 = 标题文字本身，不带前缀
- FRAME 高 92，宽覆盖整区（含最右说明卡列），fill `#00C8B3` 不透明度 100%，圆角 0
- autolayout HORIZONTAL，padding 10/24，gap 10，counterAxisAlign CENTER
- 文字 Noto Sans SC Medium 48px / lineHeight 71.04 / `#FFFFFF`
- y = 该区首排帧 y − 186
- 标题文字用短名词

**二级标题条**：同规格，fill 不透明度 0.4，宽度只覆盖子区。

紫色 `#674EFF` 标题条是旧版残留，见到要改掉。标注层的 `#00C8B3` **不是**品牌色 A1。

## 原型帧

- 尺寸统一 **402 × 872**。弹窗按内容 390×356~546；Alert 类 300×162~216。375×812 是历史残留
- 帧名：中文页面名/状态名，需要区分角色或语种时写 `<角色或语种>-<状态>`；**帧名不带编号**
- **同一 PRD 页面内帧名必须唯一**
- 横排、从左到右按流程推进；不同角色/分支另起一行
- x 步长：带侧贴说明卡的行 781；纯终态矩阵行 462
- **帧内所有界面内容按「设计系统」章节的 token 与组件实例执行**

**连线跨度约束**：连线两端节点中心的欧氏距离 ≤2000px。超出必须重排节点、拆分流程或加中继节点。

**连接线**（design 文件内）：`#00C3D0`，strokeWeight 4，ELBOWED，起点 NONE、终点 ARROW_LINES。标签 Inter Medium 16px 无底色，连接线 name 改成标签文字。

## 编号体系

- 徽标编号 = **屏内序号，纯数字，按屏重置**，不补零、不带大区字母
- 衍生说明卡用点分二级号 `1.1`、`1.2`
- 每个编号恰好出现两次：屏内徽标 1 次 + 说明卡标签行 1 次
- **功能清单不使用 F001 式编号，也不在分组标题写编号范围**
- 跨屏引用格式：`帧名-屏内序号`

## 编号徽标

远端组件 `Annotate it! – Badge nbl390kvg019lcd6`，key `<徽标组件 key>`，fill `#18A0FB`、cornerRadius 24、高 24。用组件实例，不改内部样式。

- **屏内贴法**：徽标作为原型帧内部容器的子节点，压在被说明的控件上
- **卡片贴法**：徽标是说明卡标签行 autolayout 的第 1 个子节点

贴屏内徽标前先查真实父级：画板内子节点坐标相对其真实父级（常是中间 Frame 而非画板），用 `absoluteBoundingBox` 差值换算。

**徽标不要与界面内的圆形数字角标混淆**：未读消息角标同样是蓝底白字圆形，同屏出现会造成编号歧义。

徽标的 `#18A0FB` 属标注层，不计入屏内 token 合规扫描。

## 说明卡

**结构与视觉**

```
根 FRAME  name: <标题>（纯标题命名；脚本按宽 349 + 卡体结构识别）
  VERTICAL, padding 0, itemSpacing 8, 宽 FIXED 349 / 高 HUG
├─ 标签行 FRAME  HORIZONTAL, padding 0, itemSpacing 4, HUG/HUG, align CENTER
│    ├─ Badge INSTANCE
│    └─ TEXT 标题  Noto Sans SC Regular 14px / #18A0FB
└─ 卡体 FRAME  HORIZONTAL, padding 12, itemSpacing 10, 宽 FIXED 349 / 高 HUG
     fill #F6F8FD, stroke #DDE4F2 1px INSIDE, cornerRadius 6
     └─ TEXT 正文  宽 FILL(325) / 高 HUG
```

（以上是说明卡**外壳**的规格，属标注层。卡里**写什么**见「说明卡正文不写视觉规格」。）

卡标题 = 被说明的界面元素名，不是句子。

**一个状态只有一张说明卡。** 同一状态在别处再次出现时移位复用，不新建第二张。

**正文字样**：`说明：` 段 Noto Sans SC Bold 14 / `#666666`（全角冒号，后随即换行）；条目 Noto Sans SC Regular 14 / `#666666`。只有 `说明：` 一个分节标题。

**列表**
- 用 Figma **原生有序列表**（`setRangeListOptions ORDERED` + `setRangeIndentation`），层级固定 `1.` → `a.` → `i.`
- 序号由原生列表自动生成；除判断链的校验步骤前缀外，**禁止手打列表序号**

| | 序号写法 |
|---|---|
| 正 | 正文只写内容，序号交给原生列表 |
| 正 | 多步校验链在 `a.` 层加手打步骤前缀：`1-格式判断：…` |
| 反 | 正文手打 `1.` `2.` `(1)` `①` 当列表序号 |
| 反 | 在 `1.` 或 `i.` 层加 `1-` 步骤前缀（只有 `a.` 层用） |
| 反 | **给平行枚举加 `N-` 前缀**——前缀只用于有先后顺序的校验链 |
| 反 | 用空行或零宽空格分隔条目 |

**卡片定位**

```
侧贴（默认）      card.x = frame.x + 417   card.y = frame.y   同屏多卡向下堆，间距 24
底贴（终态矩阵）   card.x = frame.x         card.y = frame.y + 900
```

## 无编号卡（已废止）

**不再使用「全局说明」「本期边界」「方案前提」三类无编号卡**。这些内容必须融入具体功能的说明卡：

- 跨屏共通的技术规则（配置拉取、缓存、离线、频控）→ 并入最相关的调度类功能卡
- 本期不做的范围 → 以否定句写进对应功能卡，`不做 X` 写在讲 X 所属功能的那张卡里
- 合规前提与风险论证 → 写成对应功能卡的 `注：` 条
- 埋点、数据上报这类独立功能 → **单列一张带编号的说明卡**

**判断标准**：每条规则都要能指到一个具体控件或一次具体判断。指不到的是背景不是需求，不落卡。

这条改动同时取消了「最左无编号卡列」这个版式对象及其卡列间距 20。**大区间距口径不变**（见「页面骨架」），带编号说明卡列仍受「不得与下区标题条相交」约束，交付自检的 AABB 检查照跑。

**改完必重排**：说明卡是纵向 HUG，改正文会连锁改变卡高并撞到下方卡。每次改完都要重算该列全部卡的 y（同列间距 24）并复跑顶层 AABB 相交检查。把「改文字 → 重排 → AABB 归零」当成一个不可拆的动作。
